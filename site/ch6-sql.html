Temel SQL

SQL (Structured Query Language) hem DDL hem DML'dir: şemayı tanımlar, veriyi sorgular ve günceller. Bu sayfadaki sorgular kitabın Ch 6 örnekleridir (Q0, Q1, …); hepsini değiştirip çalıştırabilirsiniz.

  • COMPANY'nin bir tablosunu CREATE TABLE ile kısıtlarıyla (PRIMARY KEY, FOREIGN KEY, UNIQUE, NOT NULL, CHECK, DEFAULT) tanımlamak.
  • Türkçe bir soruyu SELECT-FROM-WHERE sorgusuna çevirmek: hangi tablolar, hangi join koşulları, hangi seçim koşulu, hangi sütunlar.
  • Join koşulunu unutmanın (kartezyen çarpım), DISTINCT'in ve küme işlemlerinin sonuca etkisini önceden söylemek.
  • LIKE, BETWEEN, ORDER BY, takma ad (alias) ve INSERT/UPDATE/DELETE kullanmak.

Terim eşlemesi: SQL'de table = ilişki, row = tuple, column = öznitelik. Bir fark: SQL tabloları küme değil multiset'tir (aşağıda).

Veri tanımlama (DDL)

  • Schema: bir uygulamaya ait tabloları, tipleri, kısıtları, view'ları gruplar: CREATE SCHEMA COMPANY AUTHORIZATION 'Jsmith';
  • Catalog: şemaların adlandırılmış bir topluluğu; her katalogda INFORMATION_SCHEMA adlı özel bir şema vardır. Bütünlük kısıtları yalnızca aynı katalogdaki ilişkiler arasında tanımlanabilir.
  • Base table (CREATE TABLE ile, gerçekten saklanır) ve virtual relation (CREATE VIEW, Ch 7).

COMPANY'nin tanımı (Figure 6.1/6.2)

CREATE TABLE EMPLOYEE
( Fname           VARCHAR(15)     NOT NULL,
  Minit           CHAR,
  Lname           VARCHAR(15)     NOT NULL,
  Ssn             CHAR(9)         NOT NULL,
  Bdate           DATE,
  Address         VARCHAR(30),
  Sex             CHAR,
  Salary          DECIMAL(10,2),
  Super_ssn       CHAR(9),
  Dno             INT             NOT NULL    DEFAULT 1,
  CONSTRAINT EMPPK      PRIMARY KEY (Ssn),
  CONSTRAINT EMPSUPERFK FOREIGN KEY (Super_ssn) REFERENCES EMPLOYEE(Ssn)
                        ON DELETE SET NULL  ON UPDATE CASCADE,
  CONSTRAINT EMPDEPTFK  FOREIGN KEY (Dno) REFERENCES DEPARTMENT(Dnumber)
                        ON DELETE SET DEFAULT  ON UPDATE CASCADE );   -- (MySQL: see the note below)

CREATE TABLE DEPARTMENT
( Dname           VARCHAR(15)     NOT NULL,
  Dnumber         INT             NOT NULL,
  Mgr_ssn         CHAR(9)         NOT NULL    DEFAULT '888665555',
  Mgr_start_date  DATE,
  CONSTRAINT DEPTPK    PRIMARY KEY (Dnumber),
  CONSTRAINT DEPTSK    UNIQUE (Dname),
  CONSTRAINT DEPTMGRFK FOREIGN KEY (Mgr_ssn) REFERENCES EMPLOYEE(Ssn)
                       ON DELETE SET DEFAULT  ON UPDATE CASCADE );

CREATE TABLE DEPT_LOCATIONS
( Dnumber    INT          NOT NULL,
  Dlocation  VARCHAR(15)  NOT NULL,
  PRIMARY KEY (Dnumber, Dlocation),
  FOREIGN KEY (Dnumber) REFERENCES DEPARTMENT(Dnumber)
              ON DELETE CASCADE  ON UPDATE CASCADE );

Kitabın tanımı. Bu sitedeki COMPANY bunu MySQL'de iki küçük farkla kurar: MySQL'in depolama motoru InnoDB ON DELETE SET DEFAULT'u kabul etmediği için o eylem çıkarılmıştır (silme reddedilir), ve döngüsel foreign key'ler aşağıda anlatıldığı gibi sonradan eklenir. Kurulan tanımın tamamını SQL laboratuvarında SHOW CREATE TABLE EMPLOYEE; ile görebilirsiniz.

Döngüsel foreign key'ler. EMPLOYEE.Dno → DEPARTMENT ve DEPARTMENT.Mgr_ssn → EMPLOYEE birbirine referans verir. EMPLOYEE oluşturulurken DEPARTMENT henüz yoktur. Çözüm: önce tabloları FK'sız oluşturup FK'yı sonra ALTER TABLE … ADD CONSTRAINT ile eklemek. Veri yüklerken de aynı sorun çıkar: standart SQL'de kısıt geçici olarak ertelenir (DEFERRABLE, SET CONSTRAINTS … DEFERRED) ya da önce NULL yazılıp sonra güncellenir. MySQL'de ertelenebilir kısıt yoktur; bunun yerine yükleme sırasında foreign key kontrolü kapatılıp açılır: SET FOREIGN_KEY_CHECKS = 0; … SET FOREIGN_KEY_CHECKS = 1;. Bu sitedeki COMPANY böyle yüklenir.

Veri tipleri ve domain'ler

TipÖrnekler
SayısalINTEGER/INT, SMALLINT, FLOAT/REAL, DOUBLE PRECISION, DECIMAL(i,j) = NUMERIC(i,j): i toplam basamak (precision), j ondalık basamak (scale)
KarakterCHAR(n) sabit uzunluk (sağdan boşlukla doldurulur), VARCHAR(n) değişken uzunluk; CLOB büyük metinler. Sabitler tek tırnakla: 'Smith'. Standart SQL'de karşılaştırma büyük/küçük harfe duyarlıdır; MySQL'in varsayılan collation'ında (utf8mb4_0900_ai_ci, "ci" = case-insensitive) değildir: 'smith' = 'Smith' TRUE'dur.
BitBIT(n), BIT VARYING(n), BLOB (resim gibi büyük ikili değerler)
BooleanTRUE, FALSE, UNKNOWN (NULL yüzünden üç değerli)
Tarih/zamanDATE 'YYYY-MM-DD', TIME 'HH:MM:SS', TIMESTAMP, INTERVAL

Domain: bir tipe ad verir, değiştirmeyi kolaylaştırır: CREATE DOMAIN SSN_TYPE AS CHAR(9); Kullanıcı tanımlı tipler CREATE TYPE ile. (Standart SQL; MySQL'de CREATE DOMAIN ve CREATE TYPE yoktur, tip her sütunda ayrıca yazılır.)

Kısıtlar

  • Öznitelik kısıtları: NOT NULL, DEFAULT <değer>, CHECK: Dnumber INT NOT NULL CHECK (Dnumber > 0 AND Dnumber < 21). CHECK, CREATE DOMAIN içinde de kullanılabilir.
  • Key kısıtları: PRIMARY KEY (tek sütunsa doğrudan sütun tanımına da yazılabilir), UNIQUE (alternate/candidate key).
  • Referential integrity: FOREIGN KEY … REFERENCES. İhlalde varsayılan davranış işlemi reddetmektir (NO ACTION); bunun yerine referential triggered action tanımlanabilir: ON DELETE / ON UPDATE + SET NULL, CASCADE, SET DEFAULT.
  • Kısıtlara ad verme: CONSTRAINT EMPPK PRIMARY KEY (Ssn). Ad, kısıtı daha sonra DROP etmek ya da değiştirmek için kullanılır.
  • Tuple tabanlı CHECK: tablo tanımının sonunda, bir satırın birden çok sütununa dair: CHECK (Dept_create_date <= Mgr_start_date). Her satır eklendiğinde ya da değiştiğinde kontrol edilir.

Aşağıdaki kutu COMPANY'yi bozmamak için tabloyu demo adlı ayrı bir veritabanında oluşturur (demo.DEPT_NEW = demo veritabanındaki DEPT_NEW tablosu). Sırayla: tablo kısıtlarıyla tanımlanır, kısıtları sağlayan bir satır eklenir (Mgr_ssn verilmediği için DEFAULT değerini alır), sonra Dnumber = 25 ile CHECK'i ihlal eden bir satır denenir. Son komutun hata vermesi beklenir.

DROP TABLE IF EXISTS demo.DEPT_NEW;   -- so that the box can be run again
CREATE TABLE demo.DEPT_NEW
( Dname            VARCHAR(15)  NOT NULL UNIQUE,
  Dnumber          INT          PRIMARY KEY CHECK (Dnumber > 0 AND Dnumber < 21),
  Mgr_ssn          CHAR(9)      DEFAULT '888665555',
  Dept_create_date DATE,
  Mgr_start_date   DATE,
  CHECK (Dept_create_date <= Mgr_start_date) );
INSERT INTO demo.DEPT_NEW (Dname, Dnumber, Dept_create_date, Mgr_start_date)
       VALUES ('Research', 5, '1980-01-01', '1988-05-22');
SELECT * FROM demo.DEPT_NEW;            -- Mgr_ssn got its DEFAULT
INSERT INTO demo.DEPT_NEW VALUES ('Sales', 25, NULL, NULL, NULL);   -- violates the CHECK on Dnumber

SELECT-FROM-WHERE

SELECT <attribute list>      -- projection attributes: which columns
FROM   <table list>          -- which relations
WHERE  <condition>;          -- selection and join conditions: which rows

Karşılaştırma operatörleri: = (eşit), < (küçük), <= (küçük ya da eşit), > (büyük), >= (büyük ya da eşit), <> (eşit değil, matematikteki ≠; MySQL != yazımını da kabul eder). Örneğin Dno <> 5, departmanı 5 olmayan çalışanları seçer. Koşullar AND, OR, NOT ile birleşir.

SELECT Bdate, Address
FROM   EMPLOYEE
WHERE  Fname = 'John' AND Minit = 'B' AND Lname = 'Smith';

Q0 tek tabloluk bir sorgudur: WHERE ilişkisel cebirdeki seçime (σ), SELECT listesi izdüşüme (π) karşılık gelir. Ancak SQL tekrarları kendiliğinden silmez.

SELECT Fname, Lname, Address
FROM   EMPLOYEE, DEPARTMENT
WHERE  Dname = 'Research' AND Dnumber = Dno;

Dname = 'Research' bir selection condition, Dnumber = Dno bir join condition'dır. Böyle sorgulara select-project-join sorgusu denir.

Join koşulunu bulmak için foreign key'i izleyin: EMPLOYEE.Dno, DEPARTMENT.Dnumber'a referans veriyor (Ch 5'teki şema), o hâlde iki tablo Dno = Dnumber ile bağlanır. Koşul olmasaydı her çalışan her departmanla eşleşirdi (aşağıdaki Q10).

Soru (Q2): "Stafford'daki her proje için proje numarasını, kontrol eden departmanın numarasını ve o departmanın yöneticisinin soyadını, adresini ve doğum tarihini listeleyin."

  1. Ne isteniyor? → SELECT. Pnumber, Dnum (PROJECT'te), Lname, Address, Bdate (yöneticinin bilgileri, yani EMPLOYEE'de).
  2. Bu bilgiler hangi tablolarda? → FROM. PROJECT ve EMPLOYEE. Ama proje ile yöneticisi doğrudan bağlı değil: proje bir departmana (Dnum), departman bir yöneticiye (Mgr_ssn) bağlı. Aradaki DEPARTMENT da gerekir: FROM PROJECT, DEPARTMENT, EMPLOYEE.
  3. Tablolar nasıl bağlanıyor? → join koşulları. Her foreign key adımı bir koşul: Dnum = Dnumber (proje → departman), Mgr_ssn = Ssn (departman → yönetici). Üç tablo, iki koşul.
  4. Hangi satırlar? → seçim koşulu. Plocation = 'Stafford'.

Çalıştırmadan önce tahmin edin: Stafford'da kaç proje var ve yöneticileri kim? (PROJECT ve DEPARTMENT tablolarına aşağıdaki kutunun üstünden bakabilirsiniz.)

SELECT Pnumber, Dnum, Lname, Address, Bdate
FROM   PROJECT, DEPARTMENT, EMPLOYEE
WHERE  Dnum = Dnumber AND Mgr_ssn = Ssn AND Plocation = 'Stafford';

Sonuç: Stafford'daki iki proje (10 Computerization, 30 Newbenefits) 4 numaralı departmana ait; yöneticisi Wallace. Bu dört adım sitedeki bütün SQL sorularında işe yarar; sınavda kâğıt üzerinde de aynı sırayla düşünün.

Belirsiz adlar, takma adlar (alias), tuple değişkenleri

Farklı tablolarda aynı adlı sütunlar olabilir. Belirsizliği gidermek için sütun adı tablo adıyla nitelenir (qualify): EMPLOYEE.Dno. Aynı tablo bir sorguda iki kez geçiyorsa alias (tuple variable) zorunludur.

SELECT E.Fname, E.Lname, S.Fname, S.Lname
FROM   EMPLOYEE AS E, EMPLOYEE AS S
WHERE  E.Super_ssn = S.Ssn;

E ve S, EMPLOYEE'nin iki ayrı kopyası gibi düşünülür: E çalışan, S amir rolünde. Bu, tek düzeyli bir recursive query'dir. Borg sonuçta yoktur: amiri NULL olduğu için join koşulu sağlanmaz. Alias'larla sütunlar da yeniden adlandırılabilir: FROM EMPLOYEE AS E(Fn, Mi, Ln, Ssn, Bd, Addr, Sex, Sal, Sssn, Dno) (standart SQL; MySQL bunu temel tablolar için kabul etmez, yalnızca FROM (SELECT …) AS T(a, b) gibi alt sorgularda).

WHERE yok, * ve kartezyen çarpım

Tahmin edin: EMPLOYEE'de 8, DEPARTMENT'ta 3 satır var. İkinci sorgu kaç satır döndürür?

-- Q9: all Ssn values
SELECT Ssn FROM EMPLOYEE;
-- Q10: every combination of an employee Ssn and a department name: 8 x 3 = 24 rows
SELECT Ssn, Dname FROM EMPLOYEE, DEPARTMENT;

Join koşulunu unutmak sınavın en klasik hatasıdır: sonuç, tabloların kartezyen çarpımı olur (yanlış ve çok büyük). Kural: FROM'da n tablo varsa genellikle en az n − 1 join koşulu gerekir.

SELECT * FROM EMPLOYEE WHERE Dno = 5;
SELECT * FROM EMPLOYEE, DEPARTMENT WHERE Dname = 'Research' AND Dno = Dnumber;

Tablolar multiset'tir: ALL ve DISTINCT

SQL tekrarları kendiliğinden silmez: tekrar silmek pahalıdır (sıralama gerekir), kullanıcı tekrarları görmek isteyebilir ve aggregate fonksiyonlarda (ör. ortalama) tekrarlar önemlidir.

Tahmin edin: sekiz çalışanın maaşları 30000, 40000, 25000, 43000, 38000, 25000, 25000, 55000. İki sorgu kaçar satır döndürür?

SELECT ALL Salary FROM EMPLOYEE;        -- ALL is the default
SELECT DISTINCT Salary FROM EMPLOYEE;   -- each value once

Küme işlemleri: UNION, EXCEPT, INTERSECT

Sonuçlar kümedir (tekrarlar silinir). İki tarafın sütun sayısı ve tipleri uyumlu olmalıdır (union-compatible). Multiset sürümleri: UNION ALL, EXCEPT ALL, INTERSECT ALL.

(SELECT DISTINCT Pnumber
 FROM   PROJECT, DEPARTMENT, EMPLOYEE
 WHERE  Dnum = Dnumber AND Mgr_ssn = Ssn AND Lname = 'Smith')
UNION
(SELECT DISTINCT Pnumber
 FROM   PROJECT, WORKS_ON, EMPLOYEE
 WHERE  Pnumber = Pno AND Essn = Ssn AND Lname = 'Smith');

Tahmin edin: çalışanlar 1, 4 ve 5 numaralı departmanlarda; projeler 1, 4 ve 5 tarafından kontrol ediliyor. Her sorgunun sonucu ne olur? UNION ALL tekrarları tutar, INTERSECT ve EXCEPT tekrarları siler.

SELECT Dno FROM EMPLOYEE  UNION ALL  SELECT Dnumber FROM DEPARTMENT;   -- 8 + 3 = 11 rows
SELECT Dno FROM EMPLOYEE  INTERSECT  SELECT Dnum FROM PROJECT;         -- departments with employees AND projects
SELECT Dnumber FROM DEPARTMENT  EXCEPT  SELECT Dnum FROM PROJECT;      -- departments that control no project

LIKE, aritmetik, BETWEEN

  • LIKE: % sıfır ya da daha çok karakter, _ tam bir karakter. Bu karakterlerin kendisini aramak için kaçış karakteri: 'AB\_CD\%EF' ESCAPE '\'. Tek tırnak, içeride iki kez yazılır: 'O''Brien'.
  • Aritmetik: +, −, *, /; metin birleştirme standart SQL'de ||, MySQL'de CONCAT(a, b) (MySQL'de || varsayılan olarak OR demektir); tarih/zaman ile INTERVAL toplama, çıkarma: Bdate + INTERVAL 1 YEAR.
  • BETWEEN a AND b ≡ >= a AND <= b (iki sınır dahil).
SELECT Fname, Lname
FROM   EMPLOYEE
WHERE  Address LIKE '%Houston,%TX%';

-- a DATE compared with LIKE is read as its text 'YYYY-MM-DD': the third character is the decade
SELECT Fname, Lname, Bdate
FROM   EMPLOYEE
WHERE  Bdate LIKE '__5_______';
-- the same without relying on the text form
SELECT Fname, Lname, Bdate
FROM   EMPLOYEE
WHERE  YEAR(Bdate) BETWEEN 1950 AND 1959;

Desende 10 karakter var: __5_______ = iki herhangi karakter, 5, yedi herhangi karakter. '1955-12-08' uyar (Wong); '1965-01-09' uymaz çünkü üçüncü karakteri 6.

SELECT E.Fname, E.Lname, 1.1 * E.Salary AS Increased_sal
FROM   EMPLOYEE AS E, WORKS_ON AS W, PROJECT AS P
WHERE  E.Ssn = W.Essn AND W.Pno = P.Pnumber AND P.Pname = 'ProductX';

SELECT *
FROM   EMPLOYEE
WHERE  (Salary BETWEEN 30000 AND 40000) AND Dno = 5;

ORDER BY

SELECT   D.Dname, E.Lname, E.Fname, P.Pname
FROM     DEPARTMENT D, EMPLOYEE E, WORKS_ON W, PROJECT P
WHERE    D.Dnumber = E.Dno AND E.Ssn = W.Essn AND W.Pno = P.Pnumber
ORDER BY D.Dname DESC, E.Lname ASC, E.Fname ASC;

Varsayılan sıra ASC'dir. Her sütunun kendi yönü vardır: ORDER BY D.Dname DESC, E.Lname'de DESC yalnızca Dname içindir.

Değerlendirme sırası

Kavramsal olarak önce FROM, sonra WHERE, sonra SELECT, en son ORDER BY değerlendirilir; DBMS'in gerçek yürütme planı farklı olabilir ama sonuç bu sıraya göre tanımlanır. GROUP BY ve HAVING eklenmiş tam sıra, adım adım gösterimle Ch 7'de.

Güncelleme: INSERT, DELETE, UPDATE

INSERT

-- U1: one value per attribute, in CREATE TABLE order
INSERT INTO EMPLOYEE
VALUES ('Richard', 'K', 'Marini', '653298653', '1962-12-30', '98 Oak Forest, Katy, TX', 'M', 37000, '653298653', 4);
-- U1A: only some attributes; the rest get NULL or their DEFAULT (Dno DEFAULT 1)
INSERT INTO EMPLOYEE (Fname, Lname, Ssn)
VALUES ('Richard', 'Marini', '653298654');
SELECT Fname, Lname, Ssn, Super_ssn, Dno FROM EMPLOYEE WHERE Lname = 'Marini';

INSERT INTO EMPLOYEE (Fname, Lname, Dno)
VALUES ('Robert', 'Hatcher', 2);

Bir sorgunun sonucu da eklenebilir (U3A/U3B): geçici bir tablo oluşturup doldurmak.

DROP TABLE IF EXISTS WORKS_ON_INFO;   -- so that the box can be run again
CREATE TABLE WORKS_ON_INFO
( Emp_name      VARCHAR(15),
  Proj_name     VARCHAR(15),
  Hours_per_week DECIMAL(3,1) );
INSERT INTO WORKS_ON_INFO (Emp_name, Proj_name, Hours_per_week)
  SELECT E.Lname, P.Pname, W.Hours
  FROM   PROJECT P, WORKS_ON W, EMPLOYEE E
  WHERE  P.Pnumber = W.Pno AND W.Essn = E.Ssn;
SELECT * FROM WORKS_ON_INFO ORDER BY Emp_name;

WORKS_ON_INFO bir kopyadır: temel tablolar sonradan değişirse güncel kalmaz. Her zaman güncel bir görünüm için view kullanılır (Ch 7). Benzer şekilde CREATE TABLE D5EMPS LIKE EMPLOYEE (yalnızca yapı) ya da CREATE TABLE … AS SELECT … (yapı ve veri; standart SQL'de sona WITH DATA eklenir, MySQL'de eklenmez) ile kopya oluşturulabilir.

DELETE

WHERE koşulunu sağlayan satırları siler; koşul yoksa bütün satırları siler (tablo tanımı kalır, bunun için DROP TABLE gerekir). Referential triggered action'lar silmeyi başka tablolara yayabilir.

-- U4A: no employee is called Brown, so nothing is deleted
DELETE FROM EMPLOYEE WHERE Lname = 'Brown';
-- remove the rows that reference the employees we delete below (WORKS_ON, DEPENDENT have no CASCADE)
DELETE FROM WORKS_ON WHERE Essn = '123456789';
DELETE FROM DEPENDENT WHERE Essn = '123456789';
-- U4B: nothing else references Smith now (he manages no department and supervises nobody)
DELETE FROM EMPLOYEE WHERE Ssn = '123456789';
SELECT COUNT(*) AS employees_left FROM EMPLOYEE;   -- COUNT(*): the number of rows (aggregates: Ch 7)

UPDATE

-- U5: project 10 (Computerization) moves to Bellaire and is controlled by department 5
UPDATE PROJECT
SET    Plocation = 'Bellaire', Dnum = 5
WHERE  Pnumber = 10;
-- U6: a 10% raise for everyone in the Research department (5)
UPDATE EMPLOYEE
SET    Salary = Salary * 1.1
WHERE  Dno = 5;
SELECT Fname, Lname, Salary FROM EMPLOYEE WHERE Dno = 5;

Research'teki dört maaş 30000, 40000, 38000, 25000'den 33000, 44000, 41800, 27500'e çıkar. Atamanın sağ tarafındaki Salary eski değerdir, sol taraf yeni değeri alır. SET NULL ya da DEFAULT atayabilir. UPDATE bir seferde tek bir tabloyu değiştirir; PK değişirse FK'lar için ON UPDATE eylemleri tetiklenir.

Kendinizi sınayın

"ProductX'te çalışanların soyadları" için FROM'a EMPLOYEE, WORKS_ON, PROJECT yazdınız. WHERE'de en az kaç join koşulu gerekir?

  1. 1
  2. 3
  3. 2
  4. 0; WHERE'de yalnızca Pname = 'ProductX' yeter
FROM'daki tabloları foreign key'lerle bir zincir gibi bağlayın: EMPLOYEE.Ssn = WORKS_ON.Essn ve WORKS_ON.Pno = PROJECT.Pnumber. Üç tablo, iki halka. Sonra seçim koşulu: Pname = 'ProductX'. Sonuç Smith ve English.
SELECT Lname
FROM   EMPLOYEE, WORKS_ON, PROJECT
WHERE  Ssn = Essn AND Pno = Pnumber AND Pname = 'ProductX';

ORDER BY Dno DESC, Salary neyi ifade eder?

  1. Önce Dno'ya, sonra Salary'ye göre, ikisi de büyükten küçüğe
  2. Dno büyükten küçüğe; aynı Dno'dakiler Salary'ye göre küçükten büyüğe
  3. Önce Salary'ye, sonra Dno'ya göre
  4. Sözdizimi hatası; her sütuna yön yazılmalı
Her sıralama sütununun kendi yönü vardır ve varsayılan ASC'dir. Önce Dno'ya göre azalan sıralanır; Dno'ları eşit olan satırlar Salary'ye göre artan sıralanır.

SELECT Dno FROM EMPLOYEE UNION SELECT Dnumber FROM DEPARTMENT; kaç satır döndürür? (Çalışanların Dno değerleri: 5, 5, 4, 4, 5, 5, 4, 1; departmanlar: 5, 4, 1.)

  1. 11
  2. 8
  3. 0
  4. 3
UNION küme birleşimidir: {5, 4, 1} ∪ {5, 4, 1} = {1, 4, 5}, üç satır. Tekrarları korumak için UNION ALL yazılır (11 satır).
-- UNION: each value once
SELECT Dno FROM EMPLOYEE UNION SELECT Dnumber FROM DEPARTMENT;
-- UNION ALL keeps the duplicates: 8 + 3 = 11 rows
SELECT Dno FROM EMPLOYEE UNION ALL SELECT Dnumber FROM DEPARTMENT;

COMPANY'nin ilk hâlinde (EMPLOYEE 8 satır, bunların 4'ü 5 numaralı departmanda; DEPARTMENT 3 satır) aşağıdaki sorgu kaç satır döndürür? Tabloların satırlarını görmek için aşağıdaki tablo adlarına tıklayabilirsiniz.

SELECT Lname FROM EMPLOYEE, DEPARTMENT WHERE Dno = 5;
  1. 4
  2. 12
  3. 24
  4. 3
Kavramsal sıra: önce FROM, sonra WHERE. FROM iki tablonun kartezyen çarpımını üretir: 8 × 3 = 24 satır. WHERE yalnızca Dno = 5 olanları bırakır: 5 numaralı departmandaki 4 çalışanın her biri 3 departmanla eşleştiği için 4 × 3 = 12 satır. Smith, Wong, Narayan ve English üçer kez görünür. Aşağıdaki kutuda deneyin; sonra AND Dno = Dnumber ekleyip sonucun 4'e indiğini görün.
SELECT Lname FROM EMPLOYEE, DEPARTMENT WHERE Dno = 5;

SELECT Salary FROM EMPLOYEE ile SELECT DISTINCT Salary FROM EMPLOYEE sırasıyla kaç satır döndürür? (Maaşlar: 30000, 40000, 25000, 43000, 38000, 25000, 25000, 55000)

  1. 8 ve 8
  2. 6 ve 8
  3. 8 ve 6
  4. 6 ve 6
SQL tabloları multiset'tir; DISTINCT olmadan 25000 üç kez gelir (8 satır). DISTINCT ile 6 farklı maaş kalır.
-- one row per employee: 25000 appears three times
SELECT Salary FROM EMPLOYEE;
-- DISTINCT: each salary once
SELECT DISTINCT Salary FROM EMPLOYEE;

"Adı A ile başlayan ve tam beş harfli olan çalışanlar" için doğru koşul hangisidir?

  1. Fname LIKE 'A____'
  2. Fname LIKE 'A%'
  3. Fname = 'A____'
  4. Fname LIKE 'A%%%%'
Her _ tam bir karakter: A + dört _ = beş harf (Alicia değil, Ahmad). % herhangi uzunlukta olduğu için uzunluğu sınırlamaz; = joker karakterleri yorumlamaz.

DELETE FROM DEPARTMENT; için hangisi doğrudur?

  1. DEPARTMENT tablosunu şemadan siler.
  2. Sözdizimi hatasıdır; WHERE zorunludur.
  3. Yalnızca ilk satırı siler.
  4. Tüm satırları silmeye çalışır; tablo tanımı kalır. FK'lar (ör. PROJECT.Dnum) silmeyi engelleyebilir.
WHERE'siz DELETE bütün satırları hedefler. Tabloyu kaldırmak için DROP TABLE gerekir. COMPANY'de EMPLOYEE.Dno ve PROJECT.Dnum departmanlara referans veriyor ve bu FK'ların silmeye izin veren bir ON DELETE eylemi yok; bu yüzden MySQL silmeyi reddeder (hata 1451) ve hiçbir satır silinmez.
