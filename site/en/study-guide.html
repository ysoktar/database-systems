Short-answer concept questions

  1. What is the difference between a natural join and an equijoin?

    An equijoin is a θ-join that uses only equality comparisons, and in the result the matching attributes of the two relations stay separate (as two columns with the same values). A natural join (*) does an equijoin on the attributes with the same name and drops one of these repeated columns.

  2. Why does the foreign key go to the N side when a 1:N relationship is mapped?

    Each entity on the N side takes part in the relationship at most once, so the other side's key fits into its row as a single value. In the other direction a row on the 1 side would have to hold many values; that breaks 1NF.

  3. What is the difference between 3NF and BCNF? When is a relation in 3NF but not in BCNF?

    BCNF requires X to be a superkey for every X → A. 3NF allows one extra escape: if A is a prime attribute, X need not be a superkey. So a dependency whose left side is not a superkey and whose right side is prime (like Instructor → Course in TEACH) leaves the relation in 3NF but breaks BCNF.

  4. How is a decomposition tested for losslessness?

    For a decomposition into two parts {R1, R2}, the NJB test: if the common attributes (R1 ∩ R2) determine the rest of one of the parts, that is, if (R1 ∩ R2) → (R1 − R2) or (R1 ∩ R2) → (R2 − R1) is in F⁺, the decomposition is lossless.

  5. Why is a primary index sparse and a dense secondary index dense?

    In a primary index the file is sorted on the index field, so knowing the first record of each block (the block anchor) is enough; the anchors tell which block a wanted value falls into. In a secondary index the file is not sorted on this field; the values are scattered over the blocks, so an entry is needed for every record.

  6. What is the difference between a leaf split and an internal node split in a B+-tree?

    When a leaf splits, the last value of the left leaf is copied to the parent; the value also stays in the leaf, because all values must be in the leaves. When an internal node splits, its middle value is moved to the parent and does not stay in the internal node, because internal nodes only show the way.

  7. Define recoverable, cascadeless and strict schedules in one sentence each.

    Recoverable: a transaction does not commit before the transactions whose values it read have committed. Cascadeless: transactions read only committed values, so there is no cascading rollback. Strict: nobody reads or writes X before the last transaction that wrote X ends; undoing is just restoring the before image.

  8. What is the difference between single-quoted and double-quoted PHP strings?

    Single-quoted strings are taken literally; a $variable inside is printed as is. In double-quoted strings (and here documents) the values of variables are put into the text and escape sequences such as \n are interpreted.

  9. Which DBMS component ensures each ACID property?

    Atomicity and durability are the responsibility of the recovery subsystem, isolation of concurrency control. Consistency preservation is the responsibility of the programmer who writes the transaction and of the modules that enforce integrity constraints.

Worked problems

Problem 1: relational algebra

On COMPANY: write in relational algebra the first and last names of the employees who work on all the projects John Smith works on.

The word "all" means division. First Smith's projects and the employee–project pairs are found, then the second is divided by the first:

SMITH ← σFname='John' AND Lname='Smith'(EMPLOYEE)
SMITH_PNOS ← πPno(WORKS_ON ⋈Essn=Ssn SMITH)
SSN_PNOS ← πEssn, Pno(WORKS_ON)
SSNS(Ssn) ← SSN_PNOS ÷ SMITH_PNOS
RESULT ← πLname, Fname(SSNS * EMPLOYEE)

Smith works on projects 1 and 2; those who work on both are Smith and English. The book's Figure 8.8 is this query; in the division player of the algebra page you can see every step before and after.

Problem 2: ER-to-relational mapping

Schema: STUDENT(Sid key, Name); COURSE(Cno key, Title); INSTRUCTOR(Iid key, Name, Phones multivalued). ENROLLS is an M:N relationship between STUDENT and COURSE with the attribute Grade. TEACHES is a relationship between INSTRUCTOR (1) and COURSE (N), and every course has an instructor (the COURSE side is total). Write the tables with their primary and foreign keys.

  • Step 1: STUDENT(Sid, Name), COURSE(Cno, Title), INSTRUCTOR(Iid, Name).
  • Step 4: TEACHES is 1:N, so the foreign key goes to the N side, COURSE: COURSE(Cno, Title, Iid), Iid → INSTRUCTOR. The COURSE side is total, so Iid can be NOT NULL.
  • Step 5: ENROLLS is M:N, so it becomes a new table: ENROLLS(Sid, Cno, Grade); Sid → STUDENT, Cno → COURSE.
  • Step 6: Phones is multivalued, so it becomes a new table: INSTRUCTOR_PHONES(Iid, Phone); Iid → INSTRUCTOR.

The result is five tables. You can try similar decisions with explanations in the "You decide" section of Ch 9.

Problem 3: normalization

In the relation R(A, B, C, D, E), F = {AB → C, C → D, B → E}. Find the candidate key, the highest normal form of the relation and a lossless decomposition into BCNF. Are the dependencies preserved?

Key: A and B are on the right side of no dependency, so they are in every key. AB⁺: AB → C adds C, C → D adds D, B → E adds E; AB⁺ = {A, B, C, D, E}. The candidate key is {A, B}; the prime attributes are A and B.

Normal form: in B → E, B is part of the key and E is not prime: a partial dependency. The relation is in 1NF but not in 2NF.

Decomposition: B → E splits off R1(B, E), leaving R(A, B, C, D) (2NF). C → D is transitive (AB → C → D): R2(C, D) is split off, leaving R(A, B, C). All three relations are in BCNF: {B, E}, {C, D}, {A, B, C}. At each step the common attribute (B and C) determines the rest of one part, so the decomposition is lossless, and each of the three dependencies stays inside one part, so all are preserved.

Type this schema into the normalization tool to see the steps before and after.

Problem 4: file and index cost

r = 50,000 records, R = 200 bytes, B = 2048 bytes, unspanned placement. Key field V = 10 bytes, block pointer P = 6 bytes. (a) What are bfr and b? (b) If the file is sorted on the key, how many blocks does binary search read? (c) How many blocks does a search with a primary index read? (d) If the file is not sorted, how many blocks does a search with a dense secondary index and with its multilevel version read?

  1. bfr = ⌊2048 / 200⌋ = 10; b = ⌈50,000 / 10⌉ = 5000 blocks.
  2. ⌈log₂ 5000⌉ = 13 (2¹² = 4096 < 5000 ≤ 8192).
  3. An index entry is 16 bytes, fo = ⌊2048 / 16⌋ = 128. The 5000 entries of the primary index take ⌈5000 / 128⌉ = 40 blocks; a search reads ⌈log₂ 40⌉ + 1 = 6 + 1 = 7 blocks.
  4. The 50,000 entries of the dense secondary index take ⌈50,000 / 128⌉ = 391 blocks; a search reads ⌈log₂ 391⌉ + 1 = 9 + 1 = 10 blocks. In the multilevel version the levels are 391 → ⌈391/128⌉ = 4 → 1 blocks, so t = 3 and a search reads 4 blocks. Without an index, b/2 = 2500 blocks would be read on average.

You can check the same numbers in the cost calculator of Ch 17.

Problem 5: inserting into a B+-tree

Insert the values 20, 10, 30, 40, 50 in this order into an empty B+-tree with p = 3 and pleaf = 2. Explain every split and draw the final tree.

  • 20 and 10: a single leaf [10, 20].
  • 30: the leaf becomes [10, 20, 30] and overflows. The first ⌈3/2⌉ = 2 values stay left: [10, 20]; [30] moves to a new leaf; 20 is copied to a new root. Root [20].
  • 40: 40 > 20, so it goes to the right leaf: [30, 40].
  • 50: the right leaf becomes [30, 40, 50] and overflows: [30, 40] and [50]; 40 is copied to the root. The root can hold 2 values (p − 1 = 2), so it does not split: [20, 40].

Final tree: root [20, 40]; leaves [10, 20] → [30, 40] → [50]. In the B+-tree player, type "20 10 30 40 50" instead of "8 5 1 …" to see the tree before and after each insertion.

Problem 6: schedules

S: r1(X); r2(X); w1(Y); r3(Y); w2(Z); r3(Z); c1; c2; c3. (a) Is S conflict serializable? If so, give an equivalent serial order. (b) Is S recoverable, cascadeless, strict?

  1. There are only reads on X, so no conflict. Y: w1(Y) comes before r3(Y): T1 → T3. Z: w2(Z) comes before r3(Z): T2 → T3. The graph has no cycle: S is serializable; equivalent serial orders are T1 → T2 → T3 or T2 → T1 → T3.
  2. T3 reads Y from T1 and Z from T2, and commits after both have committed: recoverable. But T3 reads these values before T1 and T2 have committed: it is not cascadeless, and therefore not strict either.

Paste the schedule into the schedule analyzer to see the graph at every step.

Common mistakes

  • Using a join instead of division for an "all" question. A join means "at least one"; "all" needs division (or a double NOT EXISTS).
  • Putting the foreign key on the 1 side of a 1:N relationship. Many employee numbers do not fit in one department row; the foreign key always goes to the N side.
  • Mapping an M:N relationship with a foreign key. M:N always becomes a new table whose primary key combines the keys of both sides.
  • Keeping a multivalued attribute in a single column. It breaks 1NF; a separate table is needed whose primary key is the owner's key together with the value.
  • Confusing partial and transitive dependencies. Partial: the left side is part of a key. Transitive: the left side is part of no key and not a superkey either.
  • Deciding prime attributes from the primary key alone. An attribute is prime if it is part of any candidate key; the normal form cannot be told without finding all candidate keys.
  • Rounding bfr up. With unspanned placement bfr = ⌊B / R⌋; the number of blocks is rounded up: ⌈r / bfr⌉.
  • Taking the number of entries of a primary index to be the number of records. A primary index is sparse: its number of entries is the number of blocks of the data file.
  • Moving the value in a B+-tree leaf split. From a leaf it is copied to the parent; only from an internal node is it moved.
  • Confusing serializable with serial. A serializable schedule may be interleaved; what matters is that it is equivalent to a serial schedule.
  • Counting two reads as a conflict. A conflict needs at least one write.

Practice set

Which operation is needed in a relational algebra expression for "employees who do not work in the Research department"?

  1. Division (÷)
  2. Natural join (*)
  3. Difference (−)
  4. Union (∪)
"Not" questions are solved with difference: first all employees, then those satisfying the condition are found, and the second is removed from the first. Difference needs both sides to be union compatible, so only Ssn is kept on both.

A specialization is partial and overlapping. Which Step 8 option cannot be used?

  1. 8A
  2. 8B
  3. 8D
  4. None can be used
In 8B there is no table for the superclass, so an entity in no subclass is lost; that is why 8B is used only for total specializations. 8C cannot be used for this specialization either, since one type column is not enough for overlap; the right options are 8A and 8D.

R(A, B, C) and F = {A → B, B → C}. Which normal form is R in?

  1. 1NF
  2. BCNF
  3. 3NF
  4. 2NF
A is on no right side and A⁺ = {A, B, C}, so the key is A. With a single-attribute key there can be no partial dependency (2NF), but in B → C, B is not a superkey and C is not prime: a transitive dependency, a 3NF violation.

B = 1024 bytes, R = 300 bytes, r = 9000 records. How many blocks does the file take with unspanned placement?

  1. 3000
  2. 2637
  3. 2640
  4. 4500
bfr = ⌊1024 / 300⌋ = 3 (each block leaves 124 bytes free) and b = ⌈9000 / 3⌉ = 3000 blocks.

If a B-tree and a B+-tree hold the same values, which one has more search values in its internal nodes, and why?

  1. The B-tree, because all values are in internal nodes
  2. Both the same, because their orders are the same
  3. The B+-tree, because its internal nodes have no data pointers
  4. The internal nodes of a B+-tree hold no values at all
With the same block size, more values fit in an internal node of a B+-tree, because no data pointer is kept next to each value. In the book's example the internal node order of the B+-tree is 34; under the same conditions the order of a B-tree is 23.

Schedule: r1(X); w2(X); w1(X); c1; c2. Which edges are in the precedence graph?

  1. Only T1 → T2
  2. T1 → T2 and T2 → T1
  3. Only T2 → T1
  4. No edges
r1(X) and w2(X) are a read-write conflict (T1 first: T1 → T2); w2(X) and w1(X) are a write-write conflict (T2 first: T2 → T1). With both directions the graph has a cycle.

Which isolation level prevents dirty reads but allows nonrepeatable reads?

  1. READ UNCOMMITTED
  2. REPEATABLE READ
  3. SERIALIZABLE
  4. READ COMMITTED
By Table 20.1, READ COMMITTED prevents dirty reads; nonrepeatable reads and phantoms are still possible.

In PHP, while ($r = $q->fetchRow()) { print "$r[0] "; }: how many times does the loop body run when the query returns 3 rows?

  1. 3
  2. 4
  3. 1
  4. 0
fetchRow is called four times: the first three return a row each and the body runs; the fourth returns false and the while condition becomes false.
