Web database programming with PHP

So far we have run SQL directly in a console. In real applications, however, a user fills in a form on a web page, a program on the server builds SQL commands from the inputs and sends them to the database, and sends the results back as HTML. This page explains PHP, the language the book uses for this, and the PEAR DB library.

Web database programming and PHP

There are various programming techniques for adding dynamic features to web pages. PHP is one of the most widely used: an open source, general-purpose scripting language; its interpreters are free and available on almost every platform (on UNIX systems it usually comes installed).

The architecture of the book's examples has three tiers:

  • Client tier: the user's browser. It displays HTML pages and sends the values entered into forms to the server.
  • Middle tier: the web server and the PHP programs running on it. It takes the values coming from a form, sends SQL commands to the database and turns the result into HTML.
  • Bottom tier: the database server, that is, the DBMS. It runs the SQL commands and returns the results to the PHP program.

At each step the tier that is working is highlighted; the data carried between tiers, and the PHP variables and the output produced before and after, are shown side by side. The query in the database scenario really runs on the page's MySQL engine.

A simple PHP example

The book's Figure 11.1 is a PHP program that asks the user for a name and then greets them. The program is stored at http://www.myserver.com/example/greeting.php. When the browser requests this address, the web server runs the program and sends the HTML it produces to the browser.

<?php
// Printing a welcome message if the user submitted their name
// through the HTML form
if ($_POST['user_name']) {
  print("Welcome, ");
  print($_POST['user_name']);
}
else {
  // Printing the form to enter the user name since no name has
  // been entered yet
  print <<<_HTML_
  <FORM method="post" action="$_SERVER['PHP_SELF']">
  Enter your name: <input type="text" name="user_name">
  <BR/>
  <INPUT type="submit" value="SUBMIT NAME">
  </FORM>
_HTML_;
}
?>

These are the parts of the program. PHP code is written between the start tag <?php and the end tag ?>; text outside them is sent as HTML as it is. Comments are written with // to the end of the line or between /* … */. $_POST is a predefined PHP variable available everywhere (auto-global): an array holding all the values entered through the form's parameters; here $_POST['user_name'] is the value of the form's user_name field. PHP arrays are dynamic, that is, they can grow at run time. Long texts can be written in a here document opened with <<<_HTML_ and closed with _HTML_;. PHP variable names start with the $ sign.

When the program is first requested, $_POST['user_name'] is empty, so the else part runs and the form is shown (Figure 11.1b). When the user types John Smith and presses the button, the form is sent to the same program (action="$_SERVER['PHP_SELF']"); this time the if part runs and "Welcome, John Smith" is printed (Figure 11.1c–d). The first scenario of the player shows exactly these two requests.

Variables, data types and strings

PHP variable names start with $ and can contain letters, digits and the underscore (_). The type of a variable is not declared; it is set when a value is assigned. The numeric types are integers and floating-point numbers. The programming constructs are similar to other languages: for loops, while loops and if conditions. Boolean expressions use the comparison operators == (equal), != (not equal), >, >=, < and <=.

There are three main ways to express text, and the difference between them is often asked in exams:

  • Single-quoted strings: literal texts containing no variables. If you write 'Hello $name', the output shows $name literally.
  • Double-quoted strings and here documents: the values of variables inside them are put into the text (interpolation). "Hello $name" becomes Hello John if $name is John. Escape sequences such as \n are also interpreted inside double quotes.
  • The period (.) operator concatenates strings: 'Hello ' . $name.

Arrays

PHP arrays are well suited to holding query results: in a two-dimensional array the first dimension represents the rows of a table and the second the columns (attributes) within a row. There are two main types of arrays:

  • Numeric array: an integer index is associated with each element. The indexes start at zero and grow one by one.
  • Associative array: made of (key => value) pairs; elements are accessed by key.

There are two ways to loop through arrays: a foreach ($array as $key => $value) loop and a for loop using indexes. The count function returns the number of elements in the array; the sort function sorts the array by its element values. The player below runs the statements of the book's Figure 11.3 one by one and shows the array before and after each statement. Notice that sort deletes the keys of an associative array.

Functions

Functions are defined to structure a complex program and to share common sections of code. Arguments are passed by value: changing an argument inside the function does not affect the caller's variable. The book's Figure 11.4 rewrites the program of Figure 11.1 with two functions; Figure 11.5 shows a function with arguments and a return value:

function display_welcome() {
  print("Welcome, ");
  print($_POST['user_name']);
}
function display_empty_form() {
  print <<<_HTML_
  <FORM method="post" action="$_SERVER['PHP_SELF']">
  Enter your name: <INPUT type="text" name="user_name">
  <BR/>
  <INPUT type="submit" value="Submit name">
  </FORM>
_HTML_;
}
if ($_POST['user_name']) { display_welcome(); }
else { display_empty_form(); }

function course_instructor($course, $teaching_assignments) {
  if (array_key_exists($course, $teaching_assignments)) {
    $instructor = $teaching_assignments[$course];
    RETURN "$instructor is teaching $course";
  }
  else {
    RETURN "there is no $course course";
  }
}
$teaching = array('Database' => 'Smith', 'OS' => 'Carrick', 'Graphics' => 'Kam');
$teaching['Graphics'] = 'Benson'; $teaching['Data Mining'] = 'Kam';
$x = course_instructor('Database', $teaching);  // "Smith is teaching Database"
$x = course_instructor('Computer Architecture', $teaching);  // "there is no Computer Architecture course"

Server variables and forms

$_SERVER is a predefined array available everywhere that gives information about the server where the PHP interpreter runs and about the incoming request. Examples:

  • $_SERVER['SERVER_NAME']: the name of the server, for example www.uta.edu.
  • $_SERVER['REMOTE_ADDR']: the IP address of the client that sent the request; $_SERVER['REMOTE_HOST']: the client's host name (the slide writes REMOTE_ADDRESS).
  • $_SERVER['PATH_INFO']: the part of the URL after the program name; $_SERVER['QUERY_STRING']: the parameters after the ? in the URL.
  • $_SERVER['DOCUMENT_ROOT']: the root directory of the web server's files.

$_POST holds the values the user entered in HTML forms through <INPUT> tags; the keys of the array are the name attributes of the INPUT tags.

Database programming with PHP

For database access the book uses the PEAR DB library, part of the PHP Extension and Application Repository (PEAR). First the library module DB.php is loaded; the library's functions are accessed as DB::<function_name>. DB::connect('string') connects to a database; the format of the string is <DBMS software>://<user account>:<password>@<database server>. The book's Figure 11.6 shows connecting, creating a table and inserting records:

require 'DB.php';
$d = DB::connect('oci8://acct1:pass12@www.host.com/db1');
if (DB::isError($d)) { die("cannot connect - " . $d->getMessage()); }
$q = $d->query("CREATE TABLE EMPLOYEE
   (Emp_id INT,
    Name VARCHAR(15),
    Job VARCHAR(10),
    Dno INT)");
if (DB::isError($q)) { die("table creation not successful - " . $q->getMessage()); }
$d->setErrorHandling(PEAR_ERROR_DIE);
$eid = $d->nextID('EMPLOYEE');
$q = $d->query("INSERT INTO EMPLOYEE VALUES
   ($eid, $_POST['emp_name'], $_POST['emp_job'], $_POST['emp_dno'])");
$eid = $d->nextID('EMPLOYEE');
$q = $d->query('INSERT INTO EMPLOYEE VALUES (?, ?, ?, ?)',
   array($eid, $_POST['emp_name'], $_POST['emp_job'], $_POST['emp_dno']));

oci8 is the driver that connects to Oracle; for MySQL one writes mysql. If DB::connect fails it returns an error object; DB::isError checks for it and getMessage gives the error's text. $d->query takes an SQL command as a string and sends it to the database server to be executed. Instead of checking for errors after every command, $d->setErrorHandling(PEAR_ERROR_DIE) can be called: on any later error the program terminates and prints the default error message.

Collecting data from forms and inserting records

In web applications the information of the record to insert is usually collected from an HTML form. To give each new record a unique identifier PEAR DB's $d->nextID function is used: it generates a sequence of unique values for a particular table. The difference between the two INSERTs of Figure 11.6 matters. The first puts the values from the form directly into the SQL text. The second uses placeholders: ? is written in the SQL text in place of the values, and the values are given as a separate array; the library puts each value in place, quoted correctly and made safe with escape characters.

In the lab the same input goes into two queries and both really run: on the left by string concatenation, on the right with a placeholder. Try an ordinary value first, then "Malicious input". The concatenated query changes meaning because of the quote in the input and returns every record: SQL injection. The placeholder query sees the input only as a value.

Retrieving query results

The result of a SELECT query is held in a variable such as $q. $q->fetchRow() returns the next row of the result and returns empty (false) when no rows are left; so it is usually used in the condition of a while loop. The returned row is an array: $r[0] is the first column, $r[1] the second. Alternatively $allresult = $d->getAll(query) gets all rows of the result in a single variable, as a two-dimensional array, which can be looped over with foreach. The book's Figure 11.7:

$q = $d->query('SELECT Name, Dno FROM EMPLOYEE');
while ($r = $q->fetchRow()) {
  print "employee $r[0] works for department $r[1] \n";
}
$q = $d->query('SELECT Name FROM EMPLOYEE WHERE Job = ? AND Dno = ?',
   array($_POST['emp_job'], $_POST['emp_dno']));
print "employees in dept $_POST['emp_dno'] whose job is $_POST['emp_job']: \n";
while ($r = $q->fetchRow()) {
  print " $r[0] \n";
}
$allresult = $d->getAll('SELECT Name, Job, Dno FROM EMPLOYEE');
foreach ($allresult as $r) {
  print " $r[0] $r[1] $r[2] \n";
}

At each step you see the row returned by fetchRow(), the $r variable before and after, and the output the program has produced so far. When the rows run out, fetchRow() returns false and the loop ends.

Other techniques

PHP runs on the server and sends HTML to the client. There are many other languages and technologies for web database programming:

  • Java servlets: Java objects that run on the server and interact with the client; they can store information during an interaction session.
  • Java Server Pages (JSP): create dynamic web pages by scripting at the server and send them to the client; somewhat like PHP.
  • JavaScript: a scripting language that can run at the client (in the browser) or at the server. All the interactive tools of this site are written in JavaScript.
  • JSON (JavaScript Object Notation): a text-based representation of objects; it serves a function similar to XML and is used in many NoSQL systems. For example an employee can be written as {"Name": "John Smith", "Job": "Engineer", "Dno": 5}.

In the three-tier architecture, in which tier does the PHP program run?

  1. The client tier
  2. The bottom tier
  3. The middle tier
  4. All three tiers
The browser is the client tier, the web server running PHP the middle tier, and the DBMS the bottom tier. In the request player you can see which tier is working at each step.

Why should placeholders (?) be used for user input in a query?

  1. The input is used only as a value; it cannot change the structure of the query (SQL injection is prevented).
  2. The query always runs faster.
  3. They let you change the table name at run time.
  4. They give each record a unique key.
Adding values to the SQL text by string concatenation lets a quote mark typed by the user change the rest of the query. With placeholders the library quotes the value itself and adds escape characters. In the placeholder lab you can compare the two cases with "Malicious input".

When does the loop while ($r = $q->fetchRow()) end?

  1. After ten rows
  2. When the first row has been read
  3. Only when an error occurs
  4. When no rows are left in the result and fetchRow returns false
fetchRow returns the next row of the result as an array on each call. When the rows run out it returns false; the value of the assignment is false, so the while loop ends. The last step of the fetchRow player is exactly this.

For $teaching = array('Database' => 'Smith', 'OS' => 'Carrick');, what does $teaching['Database'] give after sort($teaching); runs?

  1. 'Smith'
  2. Nothing: the key no longer exists
  3. 'Carrick'
  4. An error, because sort does not work on associative arrays
sort orders the values and gives the array numeric indexes from 0; the keys of the associative array are lost. To keep the keys, asort is used; to sort by keys, ksort. In the array player you can see the sort step before and after.

Open-ended exercises

Open-ended questions of the same types as the book's exercises for this chapter. Solve them on paper first, then open the answer.

Problem 1: a query from a form

PHP code (PEAR DB) that lists the names of the employees in the department whose number comes from a form.

  1. Write the code using a placeholder. 
    $d = DB::connect('mysql://user:pass@localhost/company');
if (DB::isError($d)) { die('Connection error: ' . $d->getMessage()); }
$q = $d->query('SELECT Fname, Lname FROM EMPLOYEE WHERE Dno = ?',
               array($_POST['dno']));
while ($r = $q->fetchRow()) {
  print "$r[0] $r[1]<br>";
}

    The value from the form is not pasted into the SQL text; the driver puts it in place of ? safely.

  2. What would happen if the query text were built as "... WHERE Dno = " . $_POST['dno']?

    SQL injection: if the user types 5 OR 1=1 into the form, the condition is true for every row and all employees are listed; worse input could delete data. A placeholder makes sure the input is always treated as a value, never as SQL code.

Problem 2: fetchRow or getAll?

  1. What is the difference between a fetchRow loop and getAll when printing a 10 000-row result?

    fetchRow brings the rows one at a time; only one row is in memory at once. getAll loads the whole result into an array: shorter code, but all 10 000 rows are in memory at once. For large results the fetchRow loop is preferred.
