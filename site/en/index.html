How do the topics connect?

A database project goes in this order, and so does the book:

  1. Requirements → conceptual schema (Ch 3–4). Sentences like "every employee works for a department" become an ER/EER diagram: entities, relationships, cardinality and participation constraints.
  2. Conceptual schema → relational schema (Ch 5, the mapping in Ch 9). Entities and relationships become tables, keys become primary and foreign keys; integrity constraints protect the data.
  3. Relational schema → SQL (Ch 6–7). CREATE TABLE defines the schema; SELECT queries it, INSERT/UPDATE/DELETE change it; views, triggers and assertions add further rules.
  4. The language behind the queries (Ch 8). Relational algebra shows how SQL queries are expressed and executed inside the DBMS.
  5. The quality of the design (Ch 14). Functional dependencies and normal forms measure whether tables contain repetition and anomalies; bad tables are decomposed without loss.
  6. From the application to the database (Ch 11). A web program builds SQL commands from the values of a form and shows the results to the user.
  7. Storing on disk and fast access (Ch 16–17). Records are placed in blocks; hash files and B+-tree indexes find a record with a few block reads.
  8. Many users at the same time (Ch 20). Transactions and serializable schedules keep concurrent updates from corrupting the data.
  9. Underneath it all, the DBMS (Ch 1–2). The three-schema architecture and data independence keep programs safe from schema changes.

How to use the site

SQL boxes
