Basic SQL

SQL (Structured Query Language) is both a DDL and a DML: it defines the schema and queries and updates the data. The queries on this page are the book's Ch 6 examples (Q0, Q1, …); you can change and run all of them.

  • Define a table of COMPANY with CREATE TABLE and its constraints (PRIMARY KEY, FOREIGN KEY, UNIQUE, NOT NULL, CHECK, DEFAULT).
  • Turn a question in plain English into a SELECT-FROM-WHERE query: which tables, which join conditions, which selection condition, which columns.
  • Predict the effect on the result of forgetting a join condition (a Cartesian product), of DISTINCT and of set operations.
  • Use LIKE, BETWEEN, ORDER BY, aliases and INSERT/UPDATE/DELETE.

Matching the terms: in SQL table = relation, row = tuple, column = attribute. One difference: SQL tables are multisets, not sets (below).

Data definition (DDL)

  • Schema: groups the tables, types, constraints and views of one application: CREATE SCHEMA COMPANY AUTHORIZATION 'Jsmith';
  • Catalog: a named collection of schemas; every catalog has a special schema called INFORMATION_SCHEMA. Integrity constraints can be defined only between relations in the same catalog.
  • Base tables (created with CREATE TABLE, actually stored) and virtual relations (CREATE VIEW, Ch 7).

The book's definition. The COMPANY on this site builds it in MySQL with two small differences: since MySQL's storage engine InnoDB does not accept ON DELETE SET DEFAULT, that action is left out (the deletion is rejected), and the circular foreign keys are added afterwards as explained below. You can see the full definition that was built in the SQL lab with SHOW CREATE TABLE EMPLOYEE;.

Circular foreign keys. EMPLOYEE.Dno → DEPARTMENT and DEPARTMENT.Mgr_ssn → EMPLOYEE refer to each other. When EMPLOYEE is created, DEPARTMENT does not exist yet. The solution: first create the tables without the FKs, then add the FKs with ALTER TABLE … ADD CONSTRAINT. The same problem appears when loading data: in standard SQL the constraint is deferred temporarily (DEFERRABLE, SET CONSTRAINTS … DEFERRED) or NULL is written first and updated later. MySQL has no deferrable constraints; instead foreign key checking is turned off and on during the load: SET FOREIGN_KEY_CHECKS = 0; … SET FOREIGN_KEY_CHECKS = 1;. That is how the COMPANY on this site is loaded.

Data types and domains

Domain: gives a type a name, which makes changing it easier: CREATE DOMAIN SSN_TYPE AS CHAR(9); User-defined types with CREATE TYPE. (Standard SQL; MySQL has no CREATE DOMAIN or CREATE TYPE, the type is written in each column separately.)

Constraints

  • Attribute constraints: NOT NULL, DEFAULT <value>, CHECK: Dnumber INT NOT NULL CHECK (Dnumber > 0 AND Dnumber < 21). CHECK can also be used inside CREATE DOMAIN.
  • Key constraints: PRIMARY KEY (if it is a single column it can also be written directly in the column definition), UNIQUE (an alternate/candidate key).
  • Referential integrity: FOREIGN KEY … REFERENCES. On a violation the default behaviour is to reject the operation (NO ACTION); a referential triggered action can be specified instead: ON DELETE / ON UPDATE + SET NULL, CASCADE, SET DEFAULT.
  • Naming constraints: CONSTRAINT EMPPK PRIMARY KEY (Ssn). The name is used to DROP or change the constraint later.
  • Tuple-based CHECK: at the end of the table definition, about several columns of one row: CHECK (Dept_create_date <= Mgr_start_date). Checked whenever a row is inserted or modified.

So as not to disturb COMPANY, the box below creates the table in a separate database called demo (demo.DEPT_NEW = the table DEPT_NEW in the demo database). In order: the table is defined with its constraints, a row that satisfies the constraints is inserted (Mgr_ssn is not given, so it gets its DEFAULT value), then a row that violates the CHECK with Dnumber = 25 is tried. The last command is expected to fail.

DROP TABLE IF EXISTS demo.DEPT_NEW;   -- so that the box can be run again
CREATE TABLE demo.DEPT_NEW
( Dname            VARCHAR(15)  NOT NULL UNIQUE,
  Dnumber          INT          PRIMARY KEY CHECK (Dnumber > 0 AND Dnumber < 21),
  Mgr_ssn          CHAR(9)      DEFAULT '888665555',
  Dept_create_date DATE,
  Mgr_start_date   DATE,
  CHECK (Dept_create_date <= Mgr_start_date) );
INSERT INTO demo.DEPT_NEW (Dname, Dnumber, Dept_create_date, Mgr_start_date)
       VALUES ('Research', 5, '1980-01-01', '1988-05-22');
SELECT * FROM demo.DEPT_NEW;            -- Mgr_ssn got its DEFAULT
INSERT INTO demo.DEPT_NEW VALUES ('Sales', 25, NULL, NULL, NULL);   -- violates the CHECK on Dnumber

SELECT-FROM-WHERE

SELECT <attribute list>      -- projection attributes: which columns
FROM   <table list>          -- which relations
WHERE  <condition>;          -- selection and join conditions: which rows

Comparison operators: = (equal), < (less than), <= (less than or equal), > (greater than), >= (greater than or equal), <> (not equal, the ≠ of mathematics; MySQL also accepts !=). For example Dno <> 5 selects the employees whose department is not 5. Conditions are combined with AND, OR, NOT.

SELECT Bdate, Address
FROM   EMPLOYEE
WHERE  Fname = 'John' AND Minit = 'B' AND Lname = 'Smith';

Q0 is a single-table query: WHERE corresponds to selection (σ) in relational algebra, the SELECT list to projection (π). But SQL does not remove duplicates by itself.

SELECT Fname, Lname, Address
FROM   EMPLOYEE, DEPARTMENT
WHERE  Dname = 'Research' AND Dnumber = Dno;

Dname = 'Research' is a selection condition, Dnumber = Dno a join condition. Such queries are called select-project-join queries.

To find the join condition, follow the foreign key: EMPLOYEE.Dno references DEPARTMENT.Dnumber (the schema in Ch 5), so the two tables are connected by Dno = Dnumber. Without the condition every employee would be matched with every department (Q10 below).

Question (Q2): "For every project located in Stafford, list the project number, the controlling department number, and the department manager's last name, address and birth date."

  1. What is asked for? → SELECT. Pnumber, Dnum (in PROJECT), Lname, Address, Bdate (the manager's information, i.e. in EMPLOYEE).
  2. Which tables hold this information? → FROM. PROJECT and EMPLOYEE. But a project and its manager are not connected directly: a project belongs to a department (Dnum), a department to a manager (Mgr_ssn). DEPARTMENT in between is needed too: FROM PROJECT, DEPARTMENT, EMPLOYEE.
  3. How are the tables connected? → join conditions. Each foreign key step is a condition: Dnum = Dnumber (project → department), Mgr_ssn = Ssn (department → manager). Three tables, two conditions.
  4. Which rows? → the selection condition. Plocation = 'Stafford'.

Predict before running: how many projects are in Stafford and who are their managers? (You can look at the PROJECT and DEPARTMENT tables from above the box below.)

SELECT Pnumber, Dnum, Lname, Address, Bdate
FROM   PROJECT, DEPARTMENT, EMPLOYEE
WHERE  Dnum = Dnumber AND Mgr_ssn = Ssn AND Plocation = 'Stafford';

The result: the two projects in Stafford (10 Computerization, 30 Newbenefits) belong to department 4; its manager is Wallace. These four steps work for every SQL question on the site; in the exam, think in the same order on paper.

Ambiguous names, aliases, tuple variables

Different tables can have columns with the same name. To remove the ambiguity, the column name is qualified with the table name: EMPLOYEE.Dno. If the same table appears twice in a query an alias (tuple variable) is required.

SELECT E.Fname, E.Lname, S.Fname, S.Lname
FROM   EMPLOYEE AS E, EMPLOYEE AS S
WHERE  E.Super_ssn = S.Ssn;

Think of E and S as two separate copies of EMPLOYEE: E in the role of the employee, S in the role of the supervisor. This is a one-level recursive query. Borg is not in the result: his supervisor is NULL, so the join condition is not satisfied. Aliases can also rename the columns: FROM EMPLOYEE AS E(Fn, Mi, Ln, Ssn, Bd, Addr, Sex, Sal, Sssn, Dno) (standard SQL; MySQL does not accept this for base tables, only for subqueries such as FROM (SELECT …) AS T(a, b)).

No WHERE, * and the Cartesian product

Predict: EMPLOYEE has 8 rows, DEPARTMENT 3. How many rows does the second query return?

-- Q9: all Ssn values
SELECT Ssn FROM EMPLOYEE;
-- Q10: every combination of an employee Ssn and a department name: 8 x 3 = 24 rows
SELECT Ssn, Dname FROM EMPLOYEE, DEPARTMENT;

Forgetting the join condition is the most classic exam mistake: the result is the Cartesian product of the tables (wrong and very large). Rule: with n tables in FROM, you usually need at least n − 1 join conditions.

SELECT * FROM EMPLOYEE WHERE Dno = 5;
SELECT * FROM EMPLOYEE, DEPARTMENT WHERE Dname = 'Research' AND Dno = Dnumber;

Tables are multisets: ALL and DISTINCT

SQL does not remove duplicates by itself: removing duplicates is expensive (it needs sorting), the user may want to see the duplicates, and duplicates matter in aggregate functions (e.g. an average).

Predict: the salaries of the eight employees are 30000, 40000, 25000, 43000, 38000, 25000, 25000, 55000. How many rows does each query return?

SELECT ALL Salary FROM EMPLOYEE;        -- ALL is the default
SELECT DISTINCT Salary FROM EMPLOYEE;   -- each value once

Set operations: UNION, EXCEPT, INTERSECT

The results are sets (duplicates are removed). The two sides must have compatible numbers and types of columns (union-compatible). The multiset versions: UNION ALL, EXCEPT ALL, INTERSECT ALL.

(SELECT DISTINCT Pnumber
 FROM   PROJECT, DEPARTMENT, EMPLOYEE
 WHERE  Dnum = Dnumber AND Mgr_ssn = Ssn AND Lname = 'Smith')
UNION
(SELECT DISTINCT Pnumber
 FROM   PROJECT, WORKS_ON, EMPLOYEE
 WHERE  Pnumber = Pno AND Essn = Ssn AND Lname = 'Smith');

Predict: the employees are in departments 1, 4 and 5; the projects are controlled by 4 and 5. What is the result of each query? UNION ALL keeps duplicates, INTERSECT and EXCEPT remove them.

SELECT Dno FROM EMPLOYEE  UNION ALL  SELECT Dnumber FROM DEPARTMENT;   -- 8 + 3 = 11 rows
SELECT Dno FROM EMPLOYEE  INTERSECT  SELECT Dnum FROM PROJECT;         -- departments with employees AND projects
SELECT Dnumber FROM DEPARTMENT  EXCEPT  SELECT Dnum FROM PROJECT;      -- departments that control no project

LIKE, arithmetic, BETWEEN

  • LIKE: % zero or more characters, _ exactly one character. To search for these characters themselves, an escape character: 'AB\_CD\%EF' ESCAPE '\'. A single quote is written twice inside a string: 'O''Brien'.
  • Arithmetic: +, −, *, /; string concatenation is || in standard SQL, CONCAT(a, b) in MySQL (in MySQL || means OR by default); adding and subtracting an INTERVAL with dates/times: Bdate + INTERVAL 1 YEAR.
  • BETWEEN a AND b ≡ >= a AND <= b (both bounds included).
SELECT Fname, Lname
FROM   EMPLOYEE
WHERE  Address LIKE '%Houston,%TX%';

-- a DATE compared with LIKE is read as its text 'YYYY-MM-DD': the third character is the decade
SELECT Fname, Lname, Bdate
FROM   EMPLOYEE
WHERE  Bdate LIKE '__5_______';
-- the same without relying on the text form
SELECT Fname, Lname, Bdate
FROM   EMPLOYEE
WHERE  YEAR(Bdate) BETWEEN 1950 AND 1959;

The pattern has 10 characters: __5_______ = any two characters, 5, any seven characters. '1955-12-08' matches (Wong); '1965-01-09' does not, because its third character is 6.

SELECT E.Fname, E.Lname, 1.1 * E.Salary AS Increased_sal
FROM   EMPLOYEE AS E, WORKS_ON AS W, PROJECT AS P
WHERE  E.Ssn = W.Essn AND W.Pno = P.Pnumber AND P.Pname = 'ProductX';

SELECT *
FROM   EMPLOYEE
WHERE  (Salary BETWEEN 30000 AND 40000) AND Dno = 5;

ORDER BY

SELECT   D.Dname, E.Lname, E.Fname, P.Pname
FROM     DEPARTMENT D, EMPLOYEE E, WORKS_ON W, PROJECT P
WHERE    D.Dnumber = E.Dno AND E.Ssn = W.Essn AND W.Pno = P.Pnumber
ORDER BY D.Dname DESC, E.Lname ASC, E.Fname ASC;

The default order is ASC. Each column has its own direction: in ORDER BY D.Dname DESC, E.Lname DESC applies only to Dname.

Order of evaluation

Conceptually FROM is evaluated first, then WHERE, then SELECT, and ORDER BY last; the DBMS's actual execution plan may differ, but the result is defined by this order. The full order with GROUP BY and HAVING added, shown step by step, is in Ch 7.

Updates: INSERT, DELETE, UPDATE

INSERT

-- U1: one value per attribute, in CREATE TABLE order
INSERT INTO EMPLOYEE
VALUES ('Richard', 'K', 'Marini', '653298653', '1962-12-30', '98 Oak Forest, Katy, TX', 'M', 37000, '653298653', 4);
-- U1A: only some attributes; the rest get NULL or their DEFAULT (Dno DEFAULT 1)
INSERT INTO EMPLOYEE (Fname, Lname, Ssn)
VALUES ('Richard', 'Marini', '653298654');
SELECT Fname, Lname, Ssn, Super_ssn, Dno FROM EMPLOYEE WHERE Lname = 'Marini';

INSERT INTO EMPLOYEE (Fname, Lname, Dno)
VALUES ('Robert', 'Hatcher', 2);

The result of a query can be inserted too (U3A/U3B): creating a temporary table and filling it.

DROP TABLE IF EXISTS WORKS_ON_INFO;   -- so that the box can be run again
CREATE TABLE WORKS_ON_INFO
( Emp_name      VARCHAR(15),
  Proj_name     VARCHAR(15),
  Hours_per_week DECIMAL(3,1) );
INSERT INTO WORKS_ON_INFO (Emp_name, Proj_name, Hours_per_week)
  SELECT E.Lname, P.Pname, W.Hours
  FROM   PROJECT P, WORKS_ON W, EMPLOYEE E
  WHERE  P.Pnumber = W.Pno AND W.Essn = E.Ssn;
SELECT * FROM WORKS_ON_INFO ORDER BY Emp_name;

WORKS_ON_INFO is a copy: if the base tables change later, it does not stay up to date. For an always up-to-date view, a view is used (Ch 7). Similarly a copy can be made with CREATE TABLE D5EMPS LIKE EMPLOYEE (structure only) or CREATE TABLE … AS SELECT … (structure and data; in standard SQL WITH DATA is added at the end, in MySQL it is not).

DELETE

Deletes the rows that satisfy the WHERE condition; without a condition it deletes all the rows (the table definition remains; that needs DROP TABLE). Referential triggered actions can propagate the deletion to other tables.

-- U4A: no employee is called Brown, so nothing is deleted
DELETE FROM EMPLOYEE WHERE Lname = 'Brown';
-- remove the rows that reference the employees we delete below (WORKS_ON, DEPENDENT have no CASCADE)
DELETE FROM WORKS_ON WHERE Essn = '123456789';
DELETE FROM DEPENDENT WHERE Essn = '123456789';
-- U4B: nothing else references Smith now (he manages no department and supervises nobody)
DELETE FROM EMPLOYEE WHERE Ssn = '123456789';
SELECT COUNT(*) AS employees_left FROM EMPLOYEE;   -- COUNT(*): the number of rows (aggregates: Ch 7)

UPDATE

-- U5: project 10 (Computerization) moves to Bellaire and is controlled by department 5
UPDATE PROJECT
SET    Plocation = 'Bellaire', Dnum = 5
WHERE  Pnumber = 10;
-- U6: a 10% raise for everyone in the Research department (5)
UPDATE EMPLOYEE
SET    Salary = Salary * 1.1
WHERE  Dno = 5;
SELECT Fname, Lname, Salary FROM EMPLOYEE WHERE Dno = 5;

The four salaries in Research go from 30000, 40000, 38000, 25000 to 33000, 44000, 41800, 27500. The Salary on the right of the assignment is the old value; the left side gets the new value. SET can assign NULL or DEFAULT. UPDATE changes one table at a time; if a PK changes, the ON UPDATE actions of the FKs are triggered.

For "the last names of the employees who work on ProductX" you wrote EMPLOYEE, WORKS_ON, PROJECT in FROM. How many join conditions are needed in WHERE at least?

  1. 1
  2. 3
  3. 2
  4. 0; Pname = 'ProductX' alone in WHERE is enough
Connect the tables in FROM like a chain through the foreign keys: EMPLOYEE.Ssn = WORKS_ON.Essn and WORKS_ON.Pno = PROJECT.Pnumber. Three tables, two links. Then the selection condition: Pname = 'ProductX'. The result is Smith and English.
SELECT Lname

What does ORDER BY Dno DESC, Salary express?

  1. First by Dno, then by Salary, both from largest to smallest
  2. Dno from largest to smallest; rows with the same Dno by Salary from smallest to largest
  3. First by Salary, then by Dno
  4. A syntax error; a direction must be written for every column
Each sort column has its own direction and the default is ASC. The rows are first ordered by Dno descending; rows with equal Dno are ordered by Salary ascending.

How many rows does SELECT Dno FROM EMPLOYEE UNION SELECT Dnumber FROM DEPARTMENT; return? (The employees' Dno values: 5, 5, 4, 4, 5, 5, 4, 1; the departments: 5, 4, 1.)

  1. 11
  2. 8
  3. 0
  4. 3
UNION is set union: {5, 4, 1} ∪ {5, 4, 1} = {1, 4, 5}, three rows. To keep the duplicates write UNION ALL (11 rows).

In the starting state of COMPANY (EMPLOYEE has 8 rows, 4 of them in department 5; DEPARTMENT has 3 rows), how many rows does the following query return? Click the table names below to see the tables' rows.

SELECT Lname FROM EMPLOYEE, DEPARTMENT WHERE Dno = 5;
  1. 4
  2. 12
  3. 24
  4. 3
The conceptual order: FROM first, then WHERE. FROM produces the Cartesian product of the two tables: 8 × 3 = 24 rows. WHERE keeps only those with Dno = 5: since each of the 4 employees in department 5 is matched with 3 departments, 4 × 3 = 12 rows. Smith, Wong, Narayan and English each appear three times. How many rows do SELECT Salary FROM EMPLOYEE and SELECT DISTINCT Salary FROM EMPLOYEE return, respectively? (Salaries: 30000, 40000, 25000, 43000, 38000, 25000, 25000, 55000)

  1. 8 and 8
  2. 6 and 8
  3. 8 and 6
  4. 6 and 6
SQL tables are multisets; without DISTINCT 25000 comes three times (8 rows). With DISTINCT 6 distinct salaries remain.

Which is the correct condition for "employees whose first name starts with A and has exactly five letters"?

  1. Fname LIKE 'A____'
  2. Fname LIKE 'A%'
  3. Fname = 'A____'
  4. Fname LIKE 'A%%%%'
Each _ is exactly one character: A + four _ = five letters (Ahmad, not Alicia). % has any length, so it does not limit the length; = does not interpret wildcards.

Which is true of DELETE FROM DEPARTMENT;?

  1. It removes the DEPARTMENT table from the schema.
  2. It is a syntax error; WHERE is required.
  3. It deletes only the first row.
  4. It tries to delete all the rows; the table definition remains. FKs (e.g. PROJECT.Dnum) can prevent the deletion.
DELETE without WHERE targets all the rows. Removing the table needs DROP TABLE. In COMPANY EMPLOYEE.Dno and PROJECT.Dnum reference the departments and these FKs have no ON DELETE action that allows the deletion; so MySQL rejects it (error 1451) and no rows are deleted. You can see it in the check box.
DELETE FROM DEPARTMENT;
