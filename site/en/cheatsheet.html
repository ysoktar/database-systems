Conditions and operators

SyntaxMeaningExample in COMPANY
= <> < <= > >= Comparison: equal, not equal (<> is the ≠ of mathematics; MySQL also accepts !=), less than, less than or equal, greater than, greater than or equal. If either side is NULL the result is not TRUE or FALSE but UNKNOWN. WHERE Dno <> 5: those whose department is not 5 (Borg, Wallace, Zelaya, Jabbar)
A BETWEEN x AND y A is between x and y; both bounds included. The same as A >= x AND A <= y. Salary BETWEEN 30000 AND 40000: 30000 (Smith) and 40000 (Wong) come too
A LIKE 'pattern' Does the text match the pattern? % means any number of characters (zero included), _ exactly one character. Address LIKE '%Houston%': those whose address contains Houston; Fname LIKE 'A____': five-letter names starting with A
A IS NULL, A IS NOT NULL The only way to test whether a value is NULL. Since A = NULL is always UNKNOWN, it selects no rows. WHERE Super_ssn IS NULL: the employee with no supervisor (Borg)
A IN (…) Is A one of the values in the parentheses? The parentheses can hold a list of values or a subquery returning a single column. The same as = ANY. Pno IN (1, 2, 3); Dno IN (SELECT Dnumber FROM DEPARTMENT WHERE Dname = 'Research')
A > ALL (subquery), A > ANY (subquery) ALL: greater than every value of the subquery. ANY (= SOME): greater than at least one value. If the subquery is empty, ALL is always TRUE and ANY always FALSE. Salary > ALL (SELECT Salary FROM EMPLOYEE WHERE Dno = 5): those who earn more than everyone in 5 (Borg, Wallace)
EXISTS (subquery), NOT EXISTS (…) Does the subquery return at least one row? The result is only TRUE or FALSE, never UNKNOWN; so it is not affected by NULLs. NOT EXISTS (SELECT * FROM DEPENDENT WHERE Essn = Ssn): employees with no dependents
CASE WHEN condition THEN value … ELSE value END Chooses a value by condition: the value of the first WHEN that is TRUE, the ELSE's if none is. Can be used in SELECT, in WHERE or in the SET of an UPDATE. CASE WHEN Salary >= 40000 THEN 'high' ELSE 'low' END

NULL rules

NULL means "an unknown or missing value". SQL gives every comparison involving NULL a third value instead of TRUE or FALSE: UNKNOWN. All the rules below follow from that.

RuleWhy / example
Every comparison with NULL is UNKNOWN. Borg's Hours value is NULL. Hours > 10 is UNKNOWN for him; NOT (Hours > 10) is UNKNOWN too. So Borg is in neither result.
In AND, FALSE decides the result; in OR, TRUE. UNKNOWN AND FALSE = FALSE (one side is already false); UNKNOWN OR TRUE = TRUE (one side is already true). If it cannot be decided the result stays UNKNOWN; NOT UNKNOWN = UNKNOWN.
WHERE, HAVING and ON keep only the rows that are TRUE. UNKNOWN is discarded just like FALSE. The row counts of a condition and its negation may not add up to the table's row count: in WORKS_ON 8 + 7 = 15, but the table has 16 rows.
If the subquery returns a NULL, NOT IN selects no rows. x NOT IN (a, NULL) means x <> a AND x <> NULL; since the second term is UNKNOWN, the whole condition is never TRUE. The fix: use NOT EXISTS.
COUNT(*) counts rows; COUNT(A), SUM, AVG, MIN, MAX skip NULLs. In WORKS_ON COUNT(*) = 16, COUNT(Hours) = 15. AVG(Hours) is the average of 15 values; the NULL is not counted as 0.
On an empty set COUNT returns 0, the other aggregates NULL. SELECT COUNT(*), MAX(Salary) FROM EMPLOYEE WHERE Dno = 7 → 0 and NULL (there is no department 7).
In GROUP BY the NULLs form a single group of their own. If two employees had a NULL Dno, GROUP BY Dno would gather them into a single group called "NULL".
In an inner join a NULL join column matches no row. E.Super_ssn = S.Ssn is UNKNOWN for Borg: Borg is not in the list of employees matched with their supervisors (Q8). To see him too, a LEFT OUTER JOIN is needed.

Query patterns

-- "every Y" (division): no Y that x is not related to
SELECT … FROM X x
WHERE NOT EXISTS (SELECT * FROM Y y
                  WHERE NOT EXISTS (SELECT * FROM R r
                                    WHERE r.x = x.id AND r.y = y.id));

-- "no related row" (anti-join)
SELECT … FROM X x WHERE NOT EXISTS (SELECT * FROM R r WHERE r.x = x.id);
SELECT … FROM X x LEFT JOIN R r ON r.x = x.id WHERE r.x IS NULL;

-- the maximum within each group
SELECT … FROM T t
WHERE t.v = (SELECT MAX(u.v) FROM T u WHERE u.g = t.g);

-- count including zero
SELECT x.id, COUNT(r.x) FROM X x LEFT JOIN R r ON r.x = x.id
GROUP BY x.id;

-- groups whose members satisfy something overall (Q28)
… WHERE cond AND g IN (SELECT g FROM T GROUP BY g HAVING …)

Differences between the book (standard SQL) and MySQL

The syntax above is the book's, and it is what you write in the exam. The boxes on the site, however, run on MySQL. The two are the same in most places; the table below shows where they differ. If you type the book's command into a box and get an error, look at this table first.

TopicIn the book (standard SQL)In MySQLWhat does it mean?
String concatenationFname || ' ' || LnameCONCAT(Fname, ' ', Lname) In MySQL || means "or" (OR): 'a' || 'b' returns 0, not a string, and gives no error. So the mistake may go unnoticed.
Full outer joinA FULL OUTER JOIN B ON …A LEFT JOIN B ON … UNION A RIGHT JOIN B ON … MySQL has no FULL OUTER JOIN. To keep the unmatched rows of both sides, the union (UNION) of the left and right outer joins is taken; UNION keeps the matches that appear on both sides once.
General constraintCREATE ASSERTION … CHECK (NOT EXISTS …)none; a trigger instead A rule that looks at several tables (e.g. "a salary cannot exceed the supervisor's") is checked inside a trigger in MySQL, and the operation is rejected on a violation (Ch 7).
DomainCREATE DOMAIN SSN_TYPE AS CHAR(9)none A type cannot be given a name; the type is written in each column separately: Ssn CHAR(9).
Deferred constraintDEFERRABLE INITIALLY DEFERREDnone; SET FOREIGN_KEY_CHECKS = 0 When filling two tables that refer to each other (EMPLOYEE ↔ DEPARTMENT) you cannot defer the check to the end of the transaction; in MySQL foreign key checking is turned off during the load and turned back on afterwards.
Reverting to the default on deleteON DELETE SET DEFAULTnot accepted MySQL's table engine InnoDB does not support this action. The options are RESTRICT / NO ACTION (reject), CASCADE (delete them too), SET NULL.
Dropping a tableDROP TABLE T RESTRICT / CASCADEthe words can be written but have no effect In the book RESTRICT means "do not drop if anything refers to it", CASCADE "drop the referring things too". MySQL looks at neither: if another table's foreign key refers to it, the drop is always rejected (error 3730), while views are not checked.
Dropping a constraintALTER TABLE T DROP CONSTRAINT TFKALTER TABLE T DROP FOREIGN KEY TFK MySQL has its own syntax for foreign keys. That is why naming constraints (CONSTRAINT TFK …) matters in both places: a constraint without a name is hard to drop.
TriggerBEFORE INSERT OR UPDATE OF Salary … WHEN (condition) actiona separate trigger for each event; the condition in the body with IF … THEN … END IF In MySQL a trigger is tied to a single event (INSERT, UPDATE or DELETE) and there is no WHEN. Since the body has several statements inside BEGIN … END, it is written with DELIMITER //; SIGNAL SQLSTATE '45000' is used to reject the operation.
A non-grouped columnan invalid queryerror 1055 SELECT Dno, Lname, COUNT(*) … GROUP BY Dno is wrong in both places: it is undefined which Lname of a group would be shown. MySQL reports it with error 1055.
Upper/lower case'smith' = 'Smith' FALSETRUE MySQL compares strings without regard to case by default; WHERE Lname = 'smith' finds Smith. In answers based on the book, assume letters are written with the right case.
