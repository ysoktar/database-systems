Disk storage and file structures

So far we have thought about tables at the logical level. This page explains how a DBMS stores tables on disk: how records are placed in blocks, how many block reads it takes to find a record, and why hash files and RAID are used.

The storage hierarchy

Databases are usually stored on magnetic disks and accessed through physical file structures. Storage media come in three levels. Primary storage is the main memory and cache the CPU works on directly (cache: static RAM; main memory: DRAM); it is fast but expensive and limited. Secondary storage is magnetic disks, flash memory and SSDs; it is large and persistent, but much slower to access. Tertiary storage is removable media such as tape, CDs and DVDs; it is used for backup and archiving.

Most data is persistent: it is kept after programs end. Transient data exists only while a program runs. The file organization determines how records are physically placed on disk and therefore how they can be accessed.

Accessing a disk block is thousands of times slower than an operation in main memory. So the goal of file structures is to reduce the number of blocks that must be read for an operation; every cost on this page is measured in blocks.

Disks and SSDs

A hard disk stores data as bits (ones and zeros), grouped into bytes. A disk may be single- or double-sided. The concentric circles on a surface are called tracks, and tracks are divided into blocks or sectors. In a disk pack of several disks, the tracks with the same radius on all surfaces form a cylinder. Formatting divides the tracks into equal-sized disk blocks, separated by interblock gaps.

Data is always transferred between disk and main memory in units of blocks: the hardware address of a block is given to the disk I/O hardware and the block is read into or written from a buffer. A read/write head does the reading and writing; the disk controller connects the disk to the computer through standard interfaces such as SCSI, SATA or SAS. The time to access a block has three parts: moving the head to the right track (seek time), the disk rotating until the block is under the head (rotational delay), and transferring the block (block transfer time). The first two take milliseconds and are most of the cost, so reading consecutive blocks together is much cheaper than reading them one by one.

The techniques used for efficient access are: buffering data, organizing data on disk properly, reading ahead before data is requested, scheduling I/O requests in a good order, temporarily keeping writes on a log disk, and using SSDs or flash memory for recovery.

  • SSD (solid state device, flash storage): its main parts are a controller and a set of interconnected flash memory cards. It has no moving parts, so there is no seek or rotational delay and data is less fragmented. It is more expensive than an HDD. DRAM-based SSDs are even faster than flash.
  • Magnetic tape: sequential access; reaching a block means scanning all blocks before it. It is used for backup and archiving.

Buffering of blocks

If several blocks of a file are to be read, several buffers can be reserved in main memory. While one block is being read, the CPU can process the previous one; this helps when the CPU and disk I/O can work in parallel. In double buffering two buffers (A and B) are used in turn: while the disk reads into A, the CPU processes B, then they swap. Consecutive blocks are then read without waiting.

The DBMS buffer manager manages a limited number of buffers (frames) in main memory. Two pieces of information are kept for each frame: the pin count (how many processes are using the page right now; if it is not zero the page cannot be evicted) and the dirty bit (whether the page was modified; if so, it must be written to disk before it is evicted). If the requested page is not in the buffer and no frame is free, a page is chosen and evicted by a replacement strategy:

  • LRU (least recently used): the page that has not been used for the longest time is evicted.
  • FIFO (first in, first out): the page that entered the buffer first is evicted.
  • Clock: the frames are thought of as arranged in a circle, each with a "referenced" bit. A clock hand goes around: it clears the bit of a frame whose bit is 1 and moves on, and evicts the first frame whose bit is 0. It approximates LRU at a lower cost.

Placing records in blocks

A record is a collection of related values, each value corresponding to a field. Field types can be numeric, string, Boolean or date/time; large unstructured objects such as images or documents are stored as BLOBs (binary large objects). Records can be of fixed or variable length. Variable length comes from these reasons: some fields have variable length, some fields repeat, some fields are optional, or the file contains records of different types.

  • Blocking factor (bfr): the number of records that fit in a block. With block size B and record size R (R ≤ B), bfr = ⌊B / R⌋.
  • In unspanned placement a record cannot cross a block boundary, so B − bfr · R bytes are left unused in every block.
  • In spanned placement part of a record is in one block and the rest in another; a pointer at the end of the first block points to the block with the rest. Spanned placement is required when a record is larger than a block.
  • A file of r records occupies b = ⌈r / bfr⌉ blocks.

The blocks of a file can be allocated on disk contiguously, linked (each block points to the next) or indexed (the block addresses are kept in an index block). The file header (file descriptor) holds the information system programs need: the disk addresses of the blocks and the description of the record formats.

File operations and file organizations

File operations fall into two groups: retrieval operations do not change the file; update operations change it by inserting, deleting or modifying records. Records are selected by a selection condition. Typical record-level operations are: Open, Find (find the first record that satisfies a condition), Read, FindNext, Delete, Insert, Close and Scan.

Unordered (heap) files

Records are placed in the file in the order they are inserted. Insertion is very cheap: the last block is read, the record is added and the block is written back. Search, however, is linear: looking for a single record that satisfies a condition reads b/2 blocks on average, and b blocks if the record does not exist or several records are wanted. To delete, the record's block is found, the record removed and the block rewritten; or the record gets a deletion marker and the gaps are reorganized later in bulk.

Sorted files

Records are sorted on an ordering field; if this field is a key it is called the ordering key. Reading records in the order of the ordering field is very efficient, and finding the next record usually needs no new block read. For an equality condition on the ordering field a binary search can be used: about ⌈log2 b⌉ blocks are read. But insertion and deletion are expensive, because keeping the order means shifting half the records on average; so insertions are usually collected in a separate overflow file and merged periodically. A search on any field other than the ordering field is still linear.

Hashing

A hash function (randomizing function) is applied to the value of a record's hash field and gives the address of the disk block where the record is stored. This organization is called a hash file. When the search condition is an equality on the hash field, the record is usually found with a single block read. The hash field is usually a key. Hashing does not help range queries (Salary BETWEEN …), because nearby values are scattered over random blocks.

Internal hashing uses a hash table in main memory. If the hash value of an inserted record falls on an address that already holds another record, this is a collision. Collisions are resolved in three ways: open addressing (the record goes to the next free position), chaining (overflowing records are linked in a chain in an overflow area) and multiple hashing (a second hash function is tried on a collision).

External hashing is used for disk files. The target address space consists of buckets; a bucket is one disk block or a few contiguous blocks. The hash function maps a key to a bucket number; a table in the file header converts the bucket number to a disk block address. Since a bucket holds several records, collisions are less of a problem; when a bucket is full, new records go to an overflow chain attached to the bucket. In static hashing the number of buckets is fixed; as the file grows the overflow chains get longer and access slows down.

There are also methods that let the file grow and shrink. Extendible hashing keeps a directory that looks at the bits of the hash value and, when a bucket is full, splits only that bucket; performance does not degrade as the file grows. Dynamic hashing uses a tree-structured directory. Linear hashing lets the file grow and shrink without a directory by splitting buckets in order.

Other file organizations

  • Files of mixed records: related records of different types (for example a department and its employees) can be stored in the same file, physically next to each other (physical clustering). The relationships between records are set up with logical field references. Records read together then come from the same blocks.
  • B-trees: can also be used as the primary file organization; the records are stored in the leaves of the tree. B-trees are explained on the indexing page.
  • Column-based storage: each column of a table is stored separately. It is efficient for analytical queries that read a few columns over many rows.

RAID

RAID (redundant arrays of independent disks) uses several disks together to increase speed and reliability. For speed, data striping is used: data is divided over the disks and read from several disks in parallel. Striping can be at the bit level or the block level. For reliability, redundancy is used: a copy of the data (mirroring or shadowing) or parity information that lets the data be recomputed when a disk fails is stored.

LevelMethod
RAID 0Data striping, no redundancy: data is split evenly over two or more disks. It is the fastest, but if one disk fails data is lost.
RAID 1Mirrored disks: every block is written to two disks. Rebuilding after a disk failure is easiest at this level.
RAID 2Error detection and correction with memory-style Hamming codes.
RAID 3A single parity disk; the disk controller tells which disk failed.
RAID 4 and 5Block-level striping and parity. In RAID 4 parity is on one disk; in RAID 5 it is distributed over all disks, so the parity disk does not become a bottleneck.
RAID 6The P+Q redundancy scheme: with two redundancy disks it protects against two disks failing at the same time.

Modern storage architectures

  • SAN (storage area network): online storage units are configured as nodes of a high-speed network.
  • NAS (network-attached storage): servers used for file sharing; scalable, reliable, flexible and fast.
  • iSCSI: clients send SCSI commands to remote SCSI storage devices over an IP network. FCIP (Fibre Channel over IP) translates Fibre Channel commands and data into IP packets and carries them between distant SANs; FCoE (Fibre Channel over Ethernet) is similar to iSCSI but works without the IP layer.
  • Automated storage tiering: automatically moves data between storage types as needed; frequently used data moves to SSDs.
  • Object-based storage: data is managed as objects instead of files made of blocks. Each object carries metadata and a global identifier; it is well suited to scalable storage of unstructured data.

The block size is B = 512 bytes, the record size R = 100 bytes and the file has r = 30,000 records. What are the blocking factor and the number of blocks with unspanned placement?

  1. bfr = 5.12; b = 5860
  2. bfr = 5; b = 6000
  3. bfr = 6; b = 5000
  4. bfr = 5; b = 5860
bfr = ⌊B / R⌋ = ⌊512 / 100⌋ = 5; each block leaves 512 − 500 = 12 bytes unused. b = ⌈r / bfr⌉ = ⌈30,000 / 5⌉ = 6000 blocks. You can try these numbers in the calculator.

In a sorted file of 6000 blocks, about how many block reads does a binary search on the ordering key need to find a record?

  1. 3000
  2. 6000
  3. 13
  4. 1
Binary search halves the range with every block read, so ⌈log2 b⌉ = ⌈log2 6000⌉ = 13 blocks are read. If the same file were a heap, b/2 = 3000 blocks would be read on average.

For which query does a hash file (hash field Ssn) help the least?

  1. Employees whose Ssn is between 100000000 and 200000000
  2. The employee whose Ssn is 123456789
  3. Employees whose Ssn is 123456789 or 333445555
  4. Inserting a new employee with Ssn 999999999
A hash file is designed for equality conditions on the hash field. In range queries nearby keys are spread over different buckets, so hashing gives no order and the whole file is scanned. Sorted files or B+-trees suit range queries.

A buffer manager wants to evict a page whose pin count is 0 and whose dirty bit is 1. What happens?

  1. The page cannot be evicted, because a process is using it.
  2. The page is dropped without being written to disk.
  3. It waits until the pin count becomes 1.
  4. The page is first written to disk, then the frame is used for another page.
The pin count says how many processes are using the page right now; if it is 0 the page can be evicted. If the dirty bit is 1 the page was modified in memory and must be written to disk before eviction, otherwise the change is lost.

We want to lose no data when a disk fails and to avoid the parity disk becoming a bottleneck. Which RAID level fits?

  1. RAID 0
  2. RAID 5
  3. RAID 4
  4. RAID 3
RAID 4 and 5 use block-level striping and parity. In RAID 4 parity is on one disk, so every write loads that disk; RAID 5 removes the bottleneck by spreading parity over all disks. Against two disks failing at once, RAID 6 is needed.
