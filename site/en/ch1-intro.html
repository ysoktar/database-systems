Databases and DBMS

What is a database, what does the software that manages it (the DBMS) do, and why is the "database approach" different from the older file-based approach?

  • Tell a database, a DBMS and a database system apart; explain the four functions of a DBMS (define, construct, manipulate, share) with an example.
  • Given a problem of the file-based approach, name the DBMS feature that solves it (redundancy → controlled redundancy, …).
  • Given a description of a user, say which actor it is (DBA, casual, naive/parametric, sophisticated, …).
  • Recognize a situation where using a DBMS makes no sense, and say why.

Basic definitions

TermDefinition
DataKnown facts that can be recorded and have meaning: names, telephone numbers, addresses.
DatabaseA collection of related data. The book's three implicit properties: (1) it represents some aspect of the real world (the miniworld or universe of discourse), (2) it is logically coherent and has meaning (not a random assortment of data), (3) it is designed for a specific purpose and an intended group of users.
DBMS (Database Management System)General-purpose software that makes it possible to define, construct, manipulate and share databases.
Database systemThe database + the DBMS software (+ the application programs).
Meta-dataThe description of the database: tables, columns, types, constraints. Stored in the DBMS catalog (data dictionary).

The four basic functions of a DBMS: define (specify the data types, structures and constraints), construct (store the data on a storage medium), manipulate (query, update, generate reports), share (let many users and programs access it at the same time). Protection (system and security protection) and maintenance are added to these.

An example: the UNIVERSITY database

The book's Ch 1 example is a university: the files STUDENT, COURSE, SECTION, GRADE_REPORT, PREREQUISITE. Each file is a table and each record a row; GRADE_REPORT holds a student's grade in a section, PREREQUISITE a course's prerequisite. Think of the four functions with this example: define = saying "STUDENT has the fields Name, Student_number, Class, Major"; construct = recording the students one by one; manipulate = "list Smith's transcript" or "move Smith to the second year"; share = the registrar's office, the departments and the students all using the same data at the same time.

Every SQL box on the site runs on the COMPANY database introduced in Ch 5 of the book: a company's employees (EMPLOYEE), departments (DEPARTMENT), department locations (DEPT_LOCATIONS), projects (PROJECT), who works how many hours on which project (WORKS_ON) and the employees' dependents (DEPENDENT). The rows are the ones in Figure 5.6 of the book: 8 employees, 3 departments, 6 projects. Above every box are the names of the tables it uses; click a name to open that table's rows. You can see all the tables in the schema browser of the SQL lab.

You will learn SQL in Ch 6; for now run the box below only to see the self-describing property. The box reads the COLUMNS table in the DBMS catalog (information_schema) and counts how many columns are defined for each table of COMPANY. So the definition of the tables is also inside the database, as a table that can be queried.

-- information_schema: the DBMS catalog, itself readable with SQL
SELECT TABLE_NAME, COUNT(*) AS column_count
FROM   information_schema.COLUMNS
WHERE  TABLE_SCHEMA = 'company'
GROUP BY TABLE_NAME
ORDER BY TABLE_NAME;

For EMPLOYEE you see 10: Fname, Minit, Lname, Ssn, Bdate, Address, Sex, Salary, Super_ssn, Dno. This information is stored not in the table itself but in the catalog.

Characteristics of the database approach

In the file processing approach every application defines and manages its own files; the same data is repeated in several places. In the database approach a single repository of data is defined once and everyone accesses it. The book lists four characteristics:

  1. Self-describing nature: the database contains not only the data but also a complete definition of its structure (meta-data, the catalog). The DBMS software can work with any database, because it reads the structure from the catalog.
  2. Insulation between programs and data, data abstraction:
    • Program-data independence: the file structure is not embedded in the programs; when the structure changes (e.g. a column is added) the programs do not have to change.
    • Program-operation independence: in object-oriented systems the interface (signature) of an operation is separate from its implementation.
    • Data abstraction: users are given a conceptual representation (a data model) instead of storage details.
  3. Support of multiple views of the data: different users can see different subsets of the database, or derived data (views).
  4. Sharing of data and multiuser transaction processing: many users access the data at the same time. The DBMS keeps it consistent with concurrency control. A transaction is applied entirely or not at all (atomicity) and runs as if isolated from the others (isolation).

Do not confuse the problems of file systems with the characteristics of a DBMS. Exams usually ask "the file-based approach has this problem; which feature of a DBMS solves it?": repeated data → controlled redundancy; file structure embedded in programs → program-data independence; a single view → multiple views; conflicts between simultaneous accesses → concurrency control.

Actors: who does what?

Actors on the scene

  • Database administrator (DBA): authorizes access to the database, coordinates and monitors its use, acquires hardware and software resources; responsible for security breaches and poor response time.
  • Database designer: identifies the data to be stored and chooses appropriate structures; talks to the users and designs views that meet each group's requirements.
  • End users:
    • Casual: occasionally use a query language, for different information each time (middle- or high-level managers).
    • Naive / parametric: use ready-made operations (canned transactions) over and over: bank tellers, reservation clerks.
    • Sophisticated: know the facilities of the DBMS well and write their own queries for complex requirements: engineers, scientists, analysts.
    • Standalone: keep personal databases with ready-made packages.
  • System analysts / application programmers (software engineers): analysts work out the specifications of canned transactions from end users' requirements; programmers code, test and document them.

Workers behind the scene

  • DBMS system designers and implementers: design and write the DBMS software itself (the catalog, query processing, concurrency control, recovery, … modules).
  • Tool developers: develop tools for modelling, design, performance monitoring and so on.
  • Operators and maintenance personnel: run and maintain the hardware and software environment.

The workers behind the scene are not interested in the contents of the database; they provide the DBMS itself and its environment.

Advantages of using a DBMS

  1. Controlling redundancy: storing the same data in several places wastes space and leads to inconsistency. In a DBMS the repetition is either absent or controlled. (Controlled redundancy: deliberate repetition for performance, e.g. StudentName in GRADE_REPORT; the DBMS keeps it consistent. This idea is called denormalization.)
  2. Restricting unauthorized access: a security and authorization subsystem; the DBA manages accounts and privileges.
  3. Providing persistent storage for program objects: in object-oriented databases complex program objects are stored persistently (the impedance mismatch problem is reduced).
  4. Providing storage structures and search techniques for efficient query processing: indexes, buffering/caching, query processing and optimization.
  5. Providing backup and recovery: bringing the database back to a consistent state after a hardware or software failure.
  6. Providing multiple user interfaces: query languages, programming interfaces, forms, menus, natural-language interfaces.
  7. Representing complex relationships among data.
  8. Enforcing integrity constraints: data types, uniqueness (keys), referential integrity, business rules.
  9. Permitting inferencing and actions using rules and triggers: deductive databases, triggers, stored procedures.
  10. Additional benefits: enforcing standards, shorter application development time, flexibility (programs are little affected when the structure changes), up-to-date information available to everyone at once, economies of scale.

When not to use a DBMS

A DBMS has costs: investment in hardware, software and training; the overhead of generality in defining and processing data; the overhead of the security, concurrency control, recovery and integrity functions. So ordinary files may be better when:

  • The database and the applications are simple, well defined and not expected to change.
  • There are stringent real-time requirements that the DBMS overhead cannot meet.
  • It is an embedded system with limited storage capacity.
  • No multiple-user access to the data is needed.

Also, some applications are not expressed well in the relational model: complex data models (CAD, geographic information), applications that need special operations.

A short history

  • Hierarchical and network systems (1960s–70s): relationships between records through physical pointers; programs and data intertwined.
  • The relational model (Codd, 1970): data in tables; physical storage separate from the conceptual representation; high-level query languages (SQL). Commercialized in the 1980s.
  • Object-oriented and object-relational systems (1980s–90s), the Web and XML, NoSQL and big data (2000s): very large scale, flexible schemas, high availability.

Test yourself

For a library system: (a) defining "BOOK has the fields ISBN, Title, Author", (b) entering 20 000 books into the system, (c) "list the books published after 2020", (d) students and librarians using it at the same time. Which DBMS functions are these, in order?

  1. construct, define, manipulate, share
  2. define, construct, protection, share
  3. define, construct, manipulate, maintenance
  4. define, construct, manipulate, share
Define: specify the structure and constraints (meta-data). Construct: store the data on a storage medium. Manipulate: query, update, generate reports. Share: many users and programs accessing it at the same time.

Every department of a company keeps employee information in its own file; when an employee's address changes, some files are updated and some are not. This is the direct result of which problem?

  1. Unauthorized access
  2. Lack of concurrency control
  3. Uncontrolled redundancy, and as a result inconsistency
  4. Program-data dependence
The same data is stored in several places without control (redundancy). When the copies diverge the data becomes inconsistent. A DBMS stores the data once, or uses controlled redundancy.

A bank teller uses the same ready-made operations (deposit, withdrawal, balance inquiry) every day. What kind of end user is this?

  1. Casual end user
  2. Naive (parametric) end user
  3. Sophisticated end user
  4. Standalone user
Naive/parametric users repeatedly use standard operations that were programmed and tested in advance, called canned transactions.

Which of the following best explains the self-describing property of the database approach?

  1. Users can see the data through different views.
  2. Programs are independent of the file structure.
  3. Several users can update data at the same time.
  4. The database contains, besides the data, the definition of its structure (as meta-data in the catalog).
The DBMS catalog stores the definition of every table, column, type and constraint; that is how the DBMS software can work with any database. The information_schema query above reads this catalog.

In which of these situations does using a DBMS make the least sense?

  1. The embedded control software of a washing machine, with very little memory, used by a single program
  2. A bank account system accessed from hundreds of branches at the same time
  3. A company information system where new kinds of reports are often requested
  4. A university system holding student, course and grade information
Limited storage, a single user, simple and unchanging requirements: the overhead a DBMS brings (generality, security, concurrency, recovery) does not pay off here.
