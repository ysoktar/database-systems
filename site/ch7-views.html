Kısıtlar, trigger, view, ALTER

Ch 7'nin ikinci yarısı: tabloların ötesine geçen genel kısıtlar (assertion), olaylara tepki veren kurallar (trigger), sanal tablolar (view) ve var olan bir şemayı değiştirmek (DROP, ALTER).

Assertion: genel kısıtlar (7.2.1)

CREATE ASSERTION, tek bir tabloya bağlı olmayan, deklaratif bir kısıttır. Bir ad ve bir CHECK koşulu alır; koşul, veritabanının her durumunda TRUE olmalıdır. Kalıp: "ihlal eden satırları bulan bir sorgu yaz, başına NOT EXISTS koy."

-- "An employee's salary must not be greater than the salary of the manager of the department
--  that the employee works for."
CREATE ASSERTION SALARY_CONSTRAINT
CHECK ( NOT EXISTS ( SELECT *
                     FROM   EMPLOYEE E, EMPLOYEE M, DEPARTMENT D
                     WHERE  E.Salary > M.Salary
                       AND  E.Dno = D.Dnumber
                       AND  D.Mgr_ssn = M.Ssn ) );
  • DBMS, veritabanını bu koşulu ihlal edecek şekilde değiştiren her işlemi reddeder.
  • CHECK (öznitelik / tuple / domain) ile farkı: CHECK yalnızca ilgili satır eklendiğinde ya da değiştiğinde kontrol edilir. Bu yüzden başka tablolara bakan koşullar için güvenilir değildir. Assertion ise her zaman geçerli olmalıdır. Mümkünse CHECK tercih edilir, çünkü daha verimli uygulanır.
  • Assertion'ı pek az DBMS destekler; PostgreSQL de desteklemez. Aynı kural uygulamada trigger ile zorlanır. Ama assertion'ın içindeki sorgu her DBMS'te çalışır: boş dönmesi kuralın sağlandığı anlamına gelir.
-- violating rows before the update (none)
SELECT E.Lname AS employee, E.Salary, M.Lname AS manager, M.Salary AS mgr_salary
FROM   EMPLOYEE E, EMPLOYEE M, DEPARTMENT D
WHERE  E.Salary > M.Salary AND E.Dno = D.Dnumber AND D.Mgr_ssn = M.Ssn;
-- now break the rule and look again
UPDATE EMPLOYEE SET Salary = 45000 WHERE Lname = 'Narayan';
-- violating rows after the update
SELECT E.Lname AS employee, E.Salary, M.Lname AS manager, M.Salary AS mgr_salary
FROM   EMPLOYEE E, EMPLOYEE M, DEPARTMENT D
WHERE  E.Salary > M.Salary AND E.Dno = D.Dnumber AND D.Mgr_ssn = M.Ssn;

Trigger'lar (7.2.2)

Bir trigger, belirli olaylar gerçekleşince ve belirli koşullar sağlanınca yapılacak bir eylemi tanımlar: ECA kuralı (Event–Condition–Action).

  1. Event (olay): genellikle bir güncelleme işlemi: INSERT, DELETE, UPDATE (ya da belirli sütunlarda UPDATE OF Salary, Super_ssn). Zamanlama: BEFORE, AFTER (ya da INSTEAD OF).
  2. Condition (koşul): WHEN ile; isteğe bağlı. Koşul yoksa olay gerçekleşince eylem çalışır; varsa yalnızca koşul TRUE ise.
  3. Action (eylem): genellikle bir SQL komut dizisi ya da bir stored procedure çağrısı.

FOR EACH ROW (row-level): etkilenen her satır için bir kez; NEW ve OLD o satırın yeni ve eski hâli. FOR EACH STATEMENT: komut başına bir kez. Kitaptaki örnek (Oracle sözdizimine yakın):

-- R5: inform the supervisor whenever an employee's salary becomes greater than the supervisor's
CREATE TRIGGER SALARY_VIOLATION
BEFORE INSERT OR UPDATE OF Salary, Super_ssn ON EMPLOYEE
FOR EACH ROW
WHEN ( NEW.Salary > ( SELECT Salary FROM EMPLOYEE WHERE Ssn = NEW.Super_ssn ) )
  INFORM_SUPERVISOR(NEW.Super_ssn, NEW.Ssn);

PostgreSQL'de eylem önce bir fonksiyon olarak yazılır, trigger o fonksiyonu çağırır. Aşağıda aynı trigger: amirine bilgi vermek yerine bir NOTICE yazıyor ve olayı bir tabloya kaydediyor.

DROP TRIGGER IF EXISTS SALARY_VIOLATION ON EMPLOYEE;   -- so that the box can be run again
DROP TABLE IF EXISTS demo.SALARY_LOG;
CREATE TABLE demo.SALARY_LOG (Super_ssn CHAR(9), Ssn CHAR(9), New_salary DECIMAL(10,2), At TIMESTAMP);

CREATE OR REPLACE FUNCTION inform_supervisor() RETURNS trigger AS $$
BEGIN
  INSERT INTO demo.SALARY_LOG VALUES (NEW.Super_ssn, NEW.Ssn, NEW.Salary, LOCALTIMESTAMP);
  RAISE NOTICE 'Supervisor % informed: % now earns %', NEW.Super_ssn, NEW.Ssn, NEW.Salary;
  RETURN NEW;            -- BEFORE trigger: return the row to be written
END $$ LANGUAGE plpgsql;

CREATE TRIGGER SALARY_VIOLATION
BEFORE INSERT OR UPDATE OF Salary, Super_ssn ON EMPLOYEE
FOR EACH ROW
WHEN ( NEW.Salary > 40000 )     -- PostgreSQL does not allow subqueries in WHEN: the full test is below
EXECUTE FUNCTION inform_supervisor();

-- Smith (supervisor Wong, 40000) gets a raise to 42000: the trigger fires
UPDATE EMPLOYEE SET Salary = 42000 WHERE Ssn = '123456789';
SELECT * FROM demo.SALARY_LOG;

PostgreSQL trigger'ın WHEN koşulunda alt sorguya izin vermez. Bu yüzden amirle karşılaştırma koşulu, gerçek uygulamada fonksiyonun içine (IF NEW.Salary > (SELECT …) THEN …) yazılır.

Trigger'ların kullanım alanları: kısıtları zorlamak (assertion'ların yerine), türetilmiş verileri güncel tutmak (ör. DEPARTMENT'a eklenmiş bir Total_sal sütunu: kitaptaki R1–R4 kuralları), kullanıcıları bir durumdan haberdar etmek, materialized view'ları güncel tutmak, denetim kaydı (audit log).

View'lar (7.3)

Bir view, başka tablolardan türetilen tek bir tablodur: virtual table. Genellikle fiziksel olarak saklanmaz. Sık sorulan karmaşık sorguları basitleştirmek, güvenlik (kullanıcıya yalnızca bazı sütunları göstermek) ve mantıksal veri bağımsızlığı için kullanılır.

-- the book writes CREATE VIEW; OR REPLACE (PostgreSQL) lets the box run again
CREATE OR REPLACE VIEW WORKS_ON1 AS
  SELECT Fname, Lname, Pname, Hours
  FROM   EMPLOYEE, PROJECT, WORKS_ON
  WHERE  Ssn = Essn AND Pno = Pnumber;

CREATE OR REPLACE VIEW DEPT_INFO (Dept_name, No_of_emps, Total_sal) AS
  SELECT   Dname, COUNT(*), SUM(Salary)
  FROM     DEPARTMENT, EMPLOYEE
  WHERE    Dnumber = Dno
  GROUP BY Dname;

-- QV1: a view is queried like a table
SELECT Fname, Lname FROM WORKS_ON1 WHERE Pname = 'ProductX';
SELECT * FROM DEPT_INFO;

View her zaman günceldir: temel tablolar değişince view'un sonucu da değişir. View tanımlanırken değil, sorgulanırken hesaplanır. (Ch 6'daki WORKS_ON_INFO kopyasıyla karşılaştırın.)

SELECT * FROM DEPT_INFO;          -- before
UPDATE EMPLOYEE SET Dno = 1 WHERE Lname = 'English';
SELECT * FROM DEPT_INFO;          -- after: Research lost one employee, Headquarters gained one

View'lar nasıl gerçekleştirilir?

  • Query modification: view'a yapılan sorgu, temel tablolar üzerinde bir sorguya çevrilir (QV1 → WORKS_ON1'in tanımıyla birleştirilmiş bir sorgu). Dezavantajı: karmaşık view'lar sık sorgulanırsa her seferinde yeniden hesaplanır.
  • View materialization: view ilk sorgulandığında fiziksel olarak saklanır (materialized view) ve temel tablolar değiştikçe güncellenir. Güncelleme stratejileri: immediate (temel tablo değişir değişmez), lazy (view sorgulanınca), periodic (belli aralıklarla, kısa süreli güncel olmama kabul edilir). Verimli güncellemeye incremental update denir.

View'lar üzerinden güncelleme

Bir view'a INSERT/UPDATE/DELETE, temel tablolarda karşılığı olan güncellemelere çevrilebiliyorsa mümkündür. Genel kurallar:

  • Tek tablolu, aggregate'siz ve temel tablonun primary key'ini (ve NOT NULL/DEFAULT'suz sütunlarını) içeren view güncellenebilir: her view satırı tam bir temel tablo satırına karşılık gelir.
  • Birden çok tablo üzerinde join içeren view'larda güncelleme genellikle belirsizdir: aynı view güncellemesi birden çok farklı temel tablo güncellemesiyle yapılabilir.
  • Gruplama ve aggregate içeren view'lar güncellenemez: DEPT_INFO.Total_sal'ı değiştirmenin temel tablolarda tek bir anlamı yoktur.
  • SQL'de güncellenebilir olması amaçlanan bir view'a WITH CHECK OPTION eklenir: view üzerinden yapılan ekleme ve güncellemeler view'un koşulunu sağlamak zorundadır, yoksa reddedilir.
-- Smith moves from ProductX to ProductY? or ProductX is renamed? Ambiguous:
UPDATE WORKS_ON1 SET Pname = 'ProductY'
WHERE  Lname = 'Smith' AND Fname = 'John' AND Pname = 'ProductX';

PostgreSQL bu güncellemeyi reddeder: join içeren view'lar otomatik güncellenebilir değildir. Kitap iki olası çeviri verir: (a) WORKS_ON'da Smith'in Pno'sunu ProductY'ninkine çevirmek (amaçlanan), (b) PROJECT'te ProductX'in adını ProductY yapmak (projenin diğer çalışanları için de görünür değişiklik; yanlış).

CREATE OR REPLACE VIEW DEPT5_EMPS AS
  SELECT Ssn, Fname, Lname, Salary, Dno
  FROM   EMPLOYEE
  WHERE  Dno = 5
  WITH CHECK OPTION;
UPDATE DEPT5_EMPS SET Salary = Salary + 1000 WHERE Lname = 'Wong';   -- fine: one base row
SELECT * FROM DEPT5_EMPS;
UPDATE DEPT5_EMPS SET Dno = 4 WHERE Lname = 'Wong';                 -- would leave the view: rejected

View'ların başka kullanımları: yetkilendirme (kullanıcıya yalnızca view üzerinde izin vermek: bir departmanın çalışanları ya da maaşsız bir EMPLOYEE görünümü) ve inline view'lar (FROM içinde tanımlanan view'lar). View'u kaldırmak için DROP VIEW WORKS_ON1;

Şema değişikliği (7.4)

DROP

  • DROP SCHEMA COMPANY CASCADE; şemayı ve içindeki her şeyi siler. RESTRICT: yalnızca şema boşsa siler.
  • DROP TABLE DEPENDENT CASCADE; tabloyu ve ona başvuran bütün kısıtları ve view'ları siler. RESTRICT: tabloya bir FK ya da view başvuruyorsa silmeyi reddeder.
  • DROP TABLE tablonun tanımını da siler; yalnızca satırları silmek için DELETE.
CREATE OR REPLACE VIEW DEP_VIEW AS SELECT Essn, Dependent_name FROM DEPENDENT;
-- RESTRICT: the view depends on DEPENDENT, so the drop is refused (the error stops this box)
DROP TABLE DEPENDENT RESTRICT;

CREATE OR REPLACE VIEW DEP_VIEW AS SELECT Essn, Dependent_name FROM DEPENDENT;
DROP TABLE DEPENDENT CASCADE;     -- also drops DEP_VIEW (see the NOTICE)
SELECT table_name FROM information_schema.tables WHERE table_schema = 'company' ORDER BY 1;

ALTER

Bir tablonun tanımını değiştirir: sütun ekleme/çıkarma, sütun tanımını değiştirme, kısıt ekleme/çıkarma.

-- add a column: existing rows get NULL (or the DEFAULT); NOT NULL is only allowed with a DEFAULT
ALTER TABLE COMPANY.EMPLOYEE ADD COLUMN Job VARCHAR(12);
UPDATE EMPLOYEE SET Job = 'Engineer' WHERE Dno = 5;
SELECT Lname, Dno, Job FROM EMPLOYEE ORDER BY Dno;
-- change a default, drop a default
ALTER TABLE COMPANY.DEPARTMENT ALTER COLUMN Mgr_ssn DROP DEFAULT;
ALTER TABLE COMPANY.DEPARTMENT ALTER COLUMN Mgr_ssn SET DEFAULT '333445555';
-- drop a named constraint, then a column
ALTER TABLE COMPANY.EMPLOYEE DROP CONSTRAINT EMPSUPERFK CASCADE;
ALTER TABLE COMPANY.EMPLOYEE DROP COLUMN Address CASCADE;
SELECT column_name FROM information_schema.columns
WHERE  table_schema = 'company' AND table_name = 'employee' ORDER BY ordinal_position;

DROP COLUMN için CASCADE (sütuna başvuran kısıt ve view'lar da silinir) ya da RESTRICT (başvuran yoksa silinir) seçilmelidir. Kısıtı kaldırabilmek için adı olmalıdır: Ch 6'da kısıtlara ad vermenin nedeni budur.

Kendinizi sınayın

CREATE VIEW V AS SELECT Dno, AVG(Salary) AS Avg_sal FROM EMPLOYEE GROUP BY Dno; view'u için hangisi doğrudur?

  1. UPDATE V SET Avg_sal = 40000 WHERE Dno = 5 geçerlidir; DBMS maaşları orantılı artırır.
  2. V güncellenemez, çünkü aggregate içeriyor; ama sorgulanabilir ve her zaman günceldir.
  3. V tanımlandığı anın verisini saklar; sonraki değişiklikleri göstermez.
  4. V'ye WITH CHECK OPTION eklenirse güncellenebilir olur.
Bir ortalamayı değiştirmenin temel tablolarda tek bir karşılığı yoktur. View sorgulandığında yeniden hesaplanır (query modification), bu yüzden hep günceldir. WITH CHECK OPTION, güncellenebilir view'larda koşulu zorlar; güncellenemezi güncellenebilir yapmaz.

"Bir çalışanın maaşı amirininkini geçemez" kuralı neden bir tuple CHECK ile güvenilir biçimde zorlanamaz?

  1. CHECK, sayısal karşılaştırma yapamaz.
  2. CHECK yalnızca primary key'lerde kullanılabilir.
  3. CHECK yalnızca o satır eklenince ya da değişince kontrol edilir; amirin maaşı düşürülünce astın satırı kontrol edilmez.
  4. CHECK, NULL değerlerde hata verir.
Kural iki farklı satıra bağlı. Amir satırı değişince ihlal oluşabilir ama ast satırındaki CHECK tetiklenmez. Böyle kurallar assertion ya da trigger ile zorlanır.

Bir trigger'ın üç bileşeni ve sırası hangisidir?

  1. Event, Condition, Action
  2. Condition, Event, Action
  3. Action, Event, Condition
  4. Event, Action, Commit
ECA: bir olay (INSERT/UPDATE/DELETE) gerçekleşir; koşul (WHEN) TRUE ise eylem çalışır. Koşul isteğe bağlıdır.

DROP TABLE DEPARTMENT RESTRICT; COMPANY'de ne olur?

  1. DEPARTMENT ve ona başvuran bütün FK'lar silinir.
  2. Yalnızca satırlar silinir, tablo tanımı kalır.
  3. DEPARTMENT silinir, EMPLOYEE.Dno değerleri NULL olur.
  4. Reddedilir: EMPLOYEE, PROJECT ve DEPT_LOCATIONS DEPARTMENT'a başvuruyor.
RESTRICT, başvuran bir kısıt ya da view varsa silmeyi reddeder. CASCADE olsaydı tablo ve başvuran kısıtlar (FK'lar) silinirdi; başvuran tabloların kendisi silinmez.
